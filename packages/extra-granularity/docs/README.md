# Документация `@feugene/extra-granularity`

Пакет — не продуктовая библиотека компонентов, а **интеграционный стенд**: он
проверяет связку `@feugene/granularity` и `@feugene/unocss-preset-granular` со
стороны *независимого потребителя*. Subpath-экспорты, `dependencies` в
`config.ts`, реестр `granular-provider` и tree-shaking ломаются в первую очередь
именно здесь, а не внутри ядра, где всё видно и так.

Отсюда единственный компонент: он нарочно маленький.

## Компоненты

- [`XgQuickForm`](./components/XgQuickForm.md) — форма из поля и кнопки поверх
  трёх примитивов ядра

Префикс `Xg`, а не `Gr`: имена не должны пересекаться с ядром, иначе жадный
резолвер авто-импорта перехватит компонент и попробует достать его из
несуществующего пути в `@feugene/granularity`.

Выбор между пакетами экосистемы — карта `docs/COMPONENT-MAP.md` в корне
репозитория.

## Сквозное — в ядре

Своих сквозных доков у пакета нет и не должно быть: он ничего не добавляет к
контрактам ядра.

| Тема | Документ ядра |
| --- | --- |
| контракт форм-контрола | `packages/granularity/docs/form-controls.md` |
| размеры | `packages/granularity/docs/sizes.md` |
| токены и темы | `packages/granularity/docs/tokens.md`, `theming.md` |
| упаковка композитного пакета | `packages/granularity/docs/companion-packages.md` |

## Правила страницы компонента

Жанр страницы, обязательные секции `## Когда брать` и `## Когда взять другое`,
запрет на рукописный перечень пропов — описаны один раз, в ядре:
`packages/granularity/docs/components.md`, раздел «Страница компонента».

Пути приведены текстом, а не ссылками: относительная ссылка в соседний пакет
работает в репозитории и ломается в опубликованном тарболе, где рядом лежит
только `dist` установленной зависимости.
