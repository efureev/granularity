# XgQuickForm

Форма из одного поля и кнопки, собранная из трёх примитивов ядра:
`GrFormField`, `GrInput`, `GrButton`. Ничего не реализует заново — только
связывает их, и в этом весь смысл: пакет доказывает, что композит **поверх**
дизайн-системы собирается без единой её правки.

Зачем существует пакет целиком — [`../README.md`](../README.md).

```vue
<XgQuickForm
  v-model="email"
  label="Электронная почта"
  submit-label="Подписаться"
  :error="serverError"
  @submit="subscribe"
/>
```

## Когда брать

- **форма из одного поля** — подписка, промокод, поиск по коду, приглашение
  по адресу: подпись, ошибка и кнопка уже связаны между собой;
- **нужен образец композита** — это референсная реализация того, как пакет
  верхнего уровня собирает компонент из subpath-импортов ядра;
- **значение приходит очищенным** — по умолчанию `submit` отдаёт значение без
  крайних пробелов; `raw` возвращает набранное как есть;
- **ошибку присылает сервер** — проп `error` подсвечивает поле и печатает текст
  под ним, без валидации на клиенте.

## Когда взять другое

| Нужно | Берите |
| --- | --- |
| Полей несколько, нужны правила и блокировка отправки | [`GrForm`](../../../granularity/docs/components/GrForm.md) |
| Своя раскладка поля с подписью и ошибкой | [`GrFormField`](../../../granularity/docs/components/GrFormField.md) + [`GrInput`](../../../granularity/docs/components/GrInput.md) |
| Поле без формы вокруг | [`GrInput`](../../../granularity/docs/components/GrInput.md) |
| Запросить одно значение окном | [`GrPromptDialog`](../../../granularity/docs/components/GrPromptDialog.md) |
| Поиск с подсказками по мере ввода | [`GrAutocomplete`](../../../granularity/docs/components/GrAutocomplete.md) |

**Второе поле — это уже `GrForm`.** Компонент намеренно не растят: как только
появляются правила, зависимости между полями и скролл к первой ошибке, оркестрация
принадлежит ядру, а не композиту. Расширять `XgQuickForm` до конструктора форм
значило бы переписать `GrForm` хуже.

## Валидации здесь нет

`error` — входной проп, а не результат проверки: компонент показывает то, что
ему сказали. Клиентская валидация живёт в `GrForm` и подключается через
`GrFormField` по имени поля, поэтому дублировать её в композите незачем — и
вредно: две реализации разошлись бы в сообщениях.

## Модель работает и без `v-model`

Значение хранится внутри, пока `modelValue` не задан, и это осознанно: форма из
одного поля часто нужна там, где состояние снаружи не нужно вовсе — обработчик
`submit` получает значение аргументом.
