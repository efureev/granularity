# SSR

Пакет ничего не рисует, поэтому расхождений разметки у него быть не может — кроме одного места.

## Адрес читается после монтирования

`useDataSource` читает строку запроса в `onMounted`, а не в `setup`. Причина в гидрации: сервер
рендерит список по умолчанию (страница 1), а в ссылке может стоять `?page=3`. Прочитай адрес в
`setup` — и первый клиентский рендер покажет третью страницу там, где сервер отдал первую. Vue
сообщит об этом предупреждением о несовпадении, а пользователь увидит мигание.

Порядок такой: серверная разметка и первый клиентский рендер совпадают, затем состояние
подтягивается из адреса и список обновляется — уже как обычное изменение, а не как расхождение.

Вне компонента (`useDataSource` вызван из стора) монтирования нет, и адрес читается сразу: гидрации
там тоже нет.

## Адаптер по умолчанию не трогает `window` на сервере

`historyUrlAdapter` проверяет наличие `window` в каждом методе: `read` возвращает пустую строку,
`write` и `subscribe` не делают ничего. Своему адаптеру стоит вести себя так же.

## Первый запрос

`immediate: true` (умолчание) шлёт запрос из `onMounted`, то есть только на клиенте. Данные для
серверного рендера подготавливает приложение — своим способом (`asyncData`, `useAsyncData`, префетч в
сторе) — и передаёт их через `rows` либо просто отрисовывает первый экран сам.
