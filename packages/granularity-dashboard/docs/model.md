# Модель раскладки

Вся арифметика живёт отдельным подпутём `@feugene/granularity-dashboard/layout` — ни Vue, ни DOM.
Её берут и без компонентов: проверить раскладку, пришедшую с сервера, или перенести её в сетку с
другим числом колонок можно и на бэкенде.

## Запись виджета

```ts
interface GrDashboardItemLayout {
  id: string          // совпадает с `itemId` у GrDashboardItem
  x: number, y: number // колонка и строка левого верхнего угла, от нуля
  w: number, h: number // размер в ячейках
  minW?, minH?, maxW?, maxH?: number
  static?: boolean    // не двигается сам и не двигается соседями
}
```

**Всё измеряется в ячейках, а не в пикселях.** Пиксели появляются ровно в двух местах: в
`layoutGeometry` и внутри одного жеста. Раскладка, записанная в пикселях, перестаёт быть верной при
первой же смене ширины окна, и восстанавливать её из хранилища было бы бессмысленно.

## Инварианты

Каждый — предмет юнит-теста, а не устного соглашения:

1. `x`, `y` целые неотрицательные; `w`, `h` целые от единицы.
2. `x + w <= cols`: виджет не свисает за правый край.
3. `minW <= w <= maxW`, `minH <= h <= maxH` — но **сетка сильнее `minW`**: см. ниже.
4. После `resolveCollisions` пересечений нет ни одного.
5. `compact(compact(l))` совпадает с `compact(l)`.
6. **Порядок массива смысла не несёт** — его несёт пара `(y, x)`. Сравнивать раскладки нужно после
   `sortLayout`, иначе перестановка элементов местами читается как изменение.
7. `static` не двигается ни сам, ни под давлением соседей.
8. `deriveLayout` не теряет и не дублирует виджеты.

Противоречие `maxW < minW` разрешается в пользу `minW`: виджет, объявивший «мне нужно не меньше
четырёх колонок», в трёх нарисуется сломанным, а лишняя колонка — всего лишь пустое место.

А вот противоречие `minW > cols` разрешается в пользу **сетки**: на двухколоночном брейкпоинте такой
виджет занимает обе колонки, а не вылезает за край. Иначе CSS Grid послушно заводит лишнюю колонку
нулевой ширины, и вся раскладка съезжает — без единой ошибки в консоли.

## Границы объявляет виджет, а не раскладка

Раскладка приходит из приложения и знает про виджет только координаты; «этот график ниже трёх строк
не читается» знает сам виджет. Поэтому `minW`/`minH`/`maxW`/`maxH` можно объявить пропами
`GrDashboardItem` — они накладываются на запись раскладки поверх неё.

## Компактизация

`compact: 'vertical'` (по умолчанию) — виджеты падают вверх, пока не упрутся в соседа или в край.
Дыр не остаётся, перенос толкает соседей вниз.

Отсюда следствие, которое стоит знать заранее: **сдвинуть виджет вниз в пустоту нельзя** — он тут же
всплывёт обратно. Это не дефект, а определение компактизации. Нужна свободная сетка — `compact: 'none'`.

Толчок распространяется по цепочке и всегда **вниз**: только это направление не спорит с
компактизацией, которая тянет всех вверх.

Столкновение со статикой **отменяет перемещение целиком**: подвинуть неподвижный виджет нельзя по
определению, а положить один поверх другого — молча испортить раскладку. То же делает
`preventCollision: true` для любого столкновения.

## Брейкпоинты

Раскладка хранится на каждый брейкпоинт:

```ts
const layout = {
  lg: [{ id: 'a', x: 0, y: 0, w: 6, h: 2 }],
  md: [{ id: 'a', x: 0, y: 0, w: 5, h: 2 }],
  // sm и xs выведутся автоматически
}
```

На ноутбуке и на планшете человек хочет разного, и одна раскладка с автосжатием этого не выражает.
Но заводить все четыре руками никто не станет — недостающая выводится из соседней.

**Донор ищется сверху, от широких к узким.** Сужать раскладку осмысленно, растягивать — нет: при
расширении появляется место, о котором исходная раскладка ничего не говорит. Донора сверху нет —
берётся ближайший снизу, это лучше пустого экрана.

Дефолты: пороги `{ lg: 1200, md: 996, sm: 768, xs: 480 }`, колонки `{ lg: 12, md: 10, sm: 6, xs: 2 }`.

**Нулевая ширина контейнера брейкпоинт не переключает.** Скрытая вкладка, свёрнутая панель,
`display: none` — это «не отрисовано», а не «самый узкий экран»; принять одно за другое значило бы
перевести дашборд на две колонки и записать эту раскладку в модель.

## Сохранение

```ts
const { layout, isRestored, reset, flush } = useDashboardLayout({
  initial: defaultLayout,
  storage: localStorageLayoutStorage(),
  key: 'analytics',
  version: 1,
  migrate: (raw, from) => migrateLayout(raw, from),
  debounce: 300,
})
```

Интерфейс `GrDashboardLayoutStorage { load, save, remove }` существует затем, чтобы раскладка могла
уехать на сервер: `localStorage` — частый случай, а не единственный.

**Разбор терпимый.** Испорченный JSON, чужая версия, потерянные поля — всё это даёт `null`, то есть
«взять `initial`». Раскладка приходит из хранилища, куда её мог записать предыдущий мажор
приложения; исключение на старте страницы — цена, которую платить не за что.

Запись идёт с паузой: жест меняет раскладку на каждой смене ячейки, и без неё один перенос давал бы
десяток обращений к хранилищу. Размонтирование дописывает отложенное.

## Виджет: шапка, отступы, прокрутка

Три решения принимает сам виджет, и все три — про содержимое, а не про место в сетке.

**Шапки может не быть.** Она появляется, только если есть что показать: `title`, слот `#header` или
`#actions`. Виджету с картой или большой цифрой шапка не нужна, и в режиме редактирования она не
возникает ради ручки — ручка живёт в панели поверх верха содержимого. Поэтому переключение режима
ничего не сдвигает: панель не занимает места в потоке.

Панель показывается по наведению и по фокусу внутри виджета, а там, где наведения не бывает
(`hover: none` — палец), видна всё время, пока идёт редактирование. Скрытая, она остаётся в DOM и в
таб-порядке: убрать её значило бы убрать ручку из обхода клавиатурой.

**Отступы — `padding`.** Не задан — ступень от `size`; `none` отдаёт виджет содержимому целиком, край
в край. Подвал этому не подчиняется: он служебная полоса, и таблица край в край с подписью под ней —
рабочий паттерн, а не противоречие.

**Что виджету разрешено — `draggable` и `resizable`.** Не заданы — действует правило сетки; заданные
сужают его для одного виджета: `:resizable="false"` убирает уголок растягивания, оставляя перенос,
`:draggable="false"` — наоборот. Отличие от `static`: тот про **раскладку** — виджет не двигается и
соседям не даёт себя двигать, — а эти два про **интерфейс**, и снимаются по отдельности. Запрет
проверяет сама сетка, а не только прячет ручку: жест и клавиатура идут через её контекст, и защита,
которая держится на «кнопку не отрисовали», снималась бы первым же прямым вызовом.

**Прокрутка — `overflow`.** `auto` по умолчанию; `hidden` снимает и полосу, и остановку `Tab` у тела
(в таб-порядок оно встаёт по факту переполнения). Виджету с картой или графиком ни то, ни другое
не нужно.

**Действия разведены по времени жизни.** `#actions` — продуктовые кнопки, видны всегда и включают
шапку. `#editActions` — действия режима редактирования (удалить виджет, открыть настройки): они
появляются только в `mode="edit"` и едут либо в шапку, либо в панель, если шапки нет.
