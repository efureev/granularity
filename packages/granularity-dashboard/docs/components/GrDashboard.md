# GrDashboard

Сетка, в которой виджеты переносят и растягивают. Режим просмотра и режим
редактирования разведены, раскладка хранится на каждый брейкпоинт и переживает
перезагрузку.

Запись раскладки, инварианты и компактизация — [`../model.md`](../model.md),
клавиши — [`../keyboard.md`](../keyboard.md), роли и объявления —
[`../a11y.md`](../a11y.md), токены — [`../theming.md`](../theming.md),
серверный рендер — [`../ssr.md`](../ssr.md).

```vue
<GrDashboard v-model:layout="layout" mode="edit">
  <GrDashboardItem item-id="revenue" title="Выручка">…</GrDashboardItem>
</GrDashboard>
```

## Когда брать

- **раскладку определяет пользователь** — аналитическая панель, рабочий стол,
  сводка под конкретную роль: набор и расположение виджетов принадлежат
  человеку, а не дизайнеру экрана;
- **раскладка обязана пережить перезагрузку** — `useDashboardLayout` кладёт её
  в `localStorage` или на сервер через интерфейс хранилища;
- **на ноутбуке и планшете нужно разное** — раскладка хранится на каждый
  брейкпоинт, недостающая выводится из соседней сверху;
- **виджеты разного размера** — `minW`/`minH`/`maxW`/`maxH` объявляет сам
  виджет, потому что «этот график ниже трёх строк не читается» знает только он.

## Когда взять другое

| Нужно | Берите |
| --- | --- |
| Раскладка фиксирована дизайном | CSS Grid и [`GrCard`](../../../granularity/docs/components/GrCard.md) |
| Две области, границу двигает пользователь | [`GrSplitter`](../../../granularity/docs/components/GrSplitter.md) |
| Порядок элементов в одном списке | [`GrSortableList`](../../../granularity/docs/components/GrSortableList.md) |
| Разделы, переключаемые вкладками | [`GrTabs`](../../../granularity/docs/components/GrTabs.md) |
| Строки таблицы с изменяемым порядком колонок | [`GrDataTable`](../../../granularity/docs/components/GrDataTable.md) |

**Дашборд — не способ разложить статичный экран.** Если пользователь ничего не
двигает, сетка виджетов даёт лишний слой состояния, хранилище и режим
редактирования там, где хватило бы CSS Grid.

## Сдвинуть виджет в пустоту по оси уплотнения нельзя

`compact` знает четыре режима: `'vertical'` (по умолчанию) тянет виджеты вверх,
`'horizontal'` — влево, `'both'` — в обе стороны, `'none'` оставляет их там, куда
положили. Отпущенный в пустоту виджет уезжает обратно — вниз при `'vertical'`,
вправо при `'horizontal'`, в обоих направлениях при `'both'`. Это не дефект, а
определение компактизации. Нужна свободная сетка с дырами — `compact: 'none'`.

Толчок при столкновении распространяется по цепочке и всегда вниз, в любом
режиме: строк бесконечно много, а вправо мешает правый край сетки. В
горизонтальных режимах это даёт сочетание, которое стоит увидеть один раз:
толкнутый вниз сосед тут же придвигается влево.

## Куда бросили — говорит сетка, кладёт приложение

Виджет, перетащенный из каталога, в раскладку сама сетка не пишет: она эмитит
`itemDrop` с ячейкой, брейкпоинтом и своими опциями раскладки, а `addItem`
вызывает потребитель — тем же способом, что и по кнопке каталога. Иначе в
раскладке появился бы виджет, для которого приложение не рисовало разметки.

Пока указатель над сеткой, подложка показывает место по-настоящему: предпросмотр
считается **тем же** `addItem` с теми же опциями, что уедут в событие. Поэтому
опции и едут в событие: посчитай приложение раскладку своими, результат разошёлся
бы с тем, что человек только что видел.

## Столкновение со статикой отменяет перенос целиком

Подвинуть `static`-виджет нельзя по определению, а положить один поверх другого
значило бы молча испортить раскладку. То же делает `preventCollision` для любого
столкновения. Половинчатого исхода — «подвинулось насколько влезло» — здесь нет:
пользователь не увидел бы, что именно не поместилось.

## Нулевая ширина — это не самый узкий экран

Скрытая вкладка, свёрнутая панель, `display: none` дают нулевую ширину
контейнера, и брейкпоинт от этого **не переключается**. Принять одно за другое
значило бы перевести дашборд на две колонки и записать эту раскладку в модель —
то есть потерять настройку пользователя из-за того, что он открыл соседнюю
вкладку.
