# Серверный рендер

Пакет живёт на браузерных API: `Image`, `URL.createObjectURL`, `canvas`,
`ResizeObserver`. Ни одного из них на сервере нет, поэтому правило простое:
**в теле `setup` браузерного API нет вовсе**.

Как это устроено в `GrImageCrop`:

- загрузка картинки висит на `onMounted` и на `watch` **без** `immediate`.
  `watch(..., { immediate: true })` выполнился бы синхронно в `setup` — то есть и
  на сервере, где `new Image()` роняет рендер;
- измерение окна (`ResizeObserver`) заводится там же и отключается в
  `onBeforeUnmount`;
- `URL.createObjectURL` вызывается только для `File` и `Blob`, которые на сервере
  и не появятся: их источник — выбор пользователя;
- разметка первого рендера не зависит от размеров: пока ширина окна не измерена,
  кадр показывает пустое состояние. Поэтому серверный HTML и первый клиентский
  рендер совпадают, и гидрация молчит.

Следствие для потребителя: компонент рендерится на сервере как пустая рамка и
оживает после монтирования. Оборачивать его в `<ClientOnly>` не нужно.

Сквозные правила серверного рендера дизайн-системы — `packages/granularity/docs/ssr.md`.
