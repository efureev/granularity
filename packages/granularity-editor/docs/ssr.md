# SSR

## Содержимое появляется после монтирования

ProseMirror требует DOM, поэтому редактор поднимается в `onMounted`. Серверная разметка — оболочка
без содержимого; участок помечен `data-allow-mismatch="children"` (механизм Vue 3.5, описан в
`packages/granularity/docs/ssr.md`), иначе гидрация сообщила бы о расхождении, которого мы добиваемся
сознательно.

Практическое следствие: **в серверном HTML текста поля нет**. Для поля ввода это правильно — оно
существует, чтобы принимать ввод, а не чтобы его индексировали.

## `v-html` в пакете отсутствует

Напрашивающееся решение — напечатать сохранённую разметку на сервере через `v-html`, чтобы первый
кадр был не пустым. Пакет так не делает.

Значение приходит от пользователя. Печать его как HTML завела бы в пакете единственную
XSS-поверхность ровно там, где данные наименее доверенные, — и обесценила бы главное свойство
редактора: разбор по схеме, который эту разметку как раз и очищает. Во всём репозитории `v-html` не
используется ни разу, и этот пакет не станет первым.

Нужен показ сохранённого текста на сервере — это отдельная задача просмотрщика, а не поля ввода.

## Что безопасно на сервере

Схемы (`createSchema`) — чистые данные и собираются без DOM, поэтому их можно вычислять где угодно.
DOM трогает только сам `Editor`, и только после монтирования.
