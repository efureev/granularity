# GrSchemaForm

Форма, разложенная по схеме бэкенда: zod или JSON Schema на входе — настоящие
поля `@feugene/granularity` на выходе. В отличие от [`GrForm`](../../../granularity/docs/components/GrForm.md),
которому поля пишут руками, здесь их даёт контракт, который уже описан на сервере.

Семейство из трёх компонентов: `GrSchemaForm` — корень, `GrSchemaField` — одно
поле по узлу схемы, `GrSchemaArrayField` — повторяемая секция.

```vue
<GrSchemaForm :schema="schema" :adapters="[zodAdapter]" v-model="model" @submit="save" />
```

## Когда брать

- **бэкенд уже описывает контракт** — zod, JSON Schema, OpenAPI: раскладывать по
  нему сорок полей руками дорого, а два описания неизбежно расходятся;
- **форм много и они однотипны** — админка, где на каждую сущность своя форма
  создания и редактирования;
- **схема приходит с сервера** — набор полей меняется без релиза фронта;
- **почти всё генерируется, а два поля свои** — слот перехватывает любое поле по
  его пути, остальные остаются сгенерированными.

## Когда взять другое

| Нужно | Берите |
| --- | --- |
| Полей немного и они известны заранее | [`GrForm`](../../../granularity/docs/components/GrForm.md) |
| Обвязка одного поля: подпись, ошибка, подсказка | [`GrFormField`](../../../granularity/docs/components/GrFormField.md) |
| Одно поле с кнопкой отправки | `XgQuickForm` из `@feugene/extra-granularity` |
| Запросить одно значение окном | [`GrPromptDialog`](../../../granularity/docs/components/GrPromptDialog.md) |
| Конструктор форм перетаскиванием | ничего: это продукт, а не компонент |

## Пакет ничего не рисует сам

Кроме сетки колонок. Оркестрацию даёт `GrForm`, обвязку и доступность —
`GrFormField`, разделы — `GrFormSection`, ввод — контролы ядра. Отсюда главное
свойство: **сгенерированная форма выглядит и ведёт себя ровно как написанная
руками** — те же тексты ошибок, та же клавиатура, та же тема.

Сетка — исключение, потому что колонок у ядра нет: `GrFormField` отвечает за одно
поле, а раскладку между полями каждый строит своей вёрсткой.

## Валидация трёхъярусная, и это видно снаружи

Что ложится в правила ядра — ложится в них: `required`, длины, границы, `email`,
`url`, файлы. Что выразимо из схемы, но не из правил, — `integer`, `multipleOf`,
строгие границы, уникальность, «обязан быть отмечен» — становится локальным
валидатором. Всё остальное — `refine`, кросс-полевые условия, ветвления — уезжает
в **одну** проверку самой схемой, которая и остаётся источником правды.

Сообщение берётся из схемы, только если автор его написал. Иначе текст даёт
резолвер ядра — с локалью ядра.

`compiledRules` в `defineExpose` отвечает на единственный вопрос, который задают
такому пакету в проде: **почему это поле не проверяется**.

## Пункты собираются под цель, а раскладка — через `uiSchema`

Схема описывает данные, а не интерфейс. Всё, что относится к виду, живёт в
`uiSchema` и адресуется **шаблонным** путём (`items.*.qty`), а не путём
конкретной строки:

```ts
const ui: GrUiSchema = {
  layout: { columns: 2, sections: [{ id: 'main', title: 'Основное', fields: ['email', 'nick'] }] },
  order: ['email', '*'],
  fields: {
    'bio': { widget: 'gr:textarea', span: 'full' },
    'items.*.qty': { label: 'Количество' },
    'company': { when: { path: 'type', eq: 'company' } },
  },
}
```

Скрытое условием поле **не участвует в проверке**: иначе отправка блокировалась
бы обязательностью поля, которого нет на экране.

## Виджет выбирает реестр, а не схема

Реестр сопоставляет узел модели с компонентом: строка с `format: email` —
`GrInput[type=email]`, до пяти вариантов — `GrRadioGroup`, больше —
`GrSelect`, массив строк — `GrInputTag`, массив объектов — повторитель.

Дефолтный набор узкий намеренно: каждая запись — это компонент в
`dependencies`, то есть его CSS в бандле **каждого** потребителя формы.
Ползунки, рейтинги и палитры живут в `extendedRenderers`, пикеры даты — в
`./renderers/chrono`; и то и другое подключается явно, см. [`../renderers.md`](../renderers.md).

## Серверные ошибки не теряются

Ответ 422 разбирается из Laravel, JSON:API и RFC 7807, путь нормализуется
(`items[0].name` → `items.0.name`), ошибка садится на поле и снимается первой же
правкой. Ошибка на поле, которого форма не рисует, показывается сводкой сверху:
«сохранение не прошло, а почему — нигде» — худший из возможных исходов.

## Ветвление — переключатель, а не поле

Способ доставки, тип платежа, вид документа: набор полей зависит от значения
одного ключа. Форма рисует переключатель вариантов (до пяти — `GrRadioGroup`,
дальше `GrSelect`) и под ним поля выбранной ветки.

Дискриминатор при этом **не рисуется отдельным полем**: им управляет
переключатель, и второе поле с тем же именем спорило бы с ним за значение.

Смена ветки переписывает значение: общие ключи сохраняются, чужие отбрасываются,
дискриминатор проставляется. Оставить чужие нельзя — схема на них ругнётся;
сбросить всё — потерять общее поле вроде примечания, которое есть у всех
вариантов.

Ветвление — структура, а не контрол, и потому оно не в реестре рендереров:
запись реестра дала бы один `GrFormField` с одной подписью на всю группу.

## Свободные ключи — приписка к объекту

`additionalProperties` со схемой значения (или `catchall` в zod) даёт список пар
«ключ — значение»: имя вводит пользователь, значение рисуется обычным контролом
по схеме. Хвостом объекта, а не полем среди полей: у пары нет ни места в схеме,
ни записи в `uiSchema`, ни порядка среди объявленных полей.

`additionalProperties: true` без схемы значения хвоста **не даёт**: ключи
разрешены, но чем рисовать значение, схема не сказала.

## Границы

- **конструктора форм перетаскиванием здесь нет и не будет** — это продукт, а не
  компонент библиотеки;
- **пакет не заменяет серверную валидацию.** Схема на клиенте экономит запрос и
  подсказывает раньше, но решение принимает сервер;
- **условия — `if/then/else`, `not` — форма не разворачивает.** Такие узлы
  помечаются для полной проверки схемой: ошибка покажется, но поле под каждый
  исход форма не построит. Ветвление по дискриминатору (`oneOf` с общим `const`,
  `z.discriminatedUnion`) она строит — см. «Ветвление» ниже;
- **объединение без дискриминатора не ветвится**: выбрать вариант нечем, и узел
  уходит в полную проверку с предупреждением.
