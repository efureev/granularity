# Значение: `Date` снаружи, кортежи внутри

## Почему так

Внутри пакета нет ни одного вычисления по `Date`. Даты считаются на кортежах
`{ y, m, d }`, время — на `{ h, min, s }`, и `Date` появляется ровно на границе:
при разборе `modelValue` и при отдаче значения наружу.

Причина не в эстетике. Арифметика по `Date` — `setDate(d + 1)`, `+ 86_400_000` —
ломается в день перевода часов: сутки там не равны 24 часам, «следующая неделя»
уезжает на час, а на границе месяца — на день. Кортеж от этого свободен по
построению: перенос месяцев считается через `y * 12 + m`, длина месяца — таблицей
с проверкой високосности. Тесты пакета гоняются в зоне с переводом часов
(`America/New_York`), где обе границы 2026 года попадают в проверки.

Второе следствие: `date-fns` и подобные пакету не нужны. Всё локале-зависимое —
первый день недели, названия месяцев и дней, 12/24-часовой вид, порядок частей
при разборе — даёт `Intl`.

## Модель компонента

```ts
type GrChronoValue = Date | null
type GrChronoRangeValue = readonly [Date, Date] | null
```

Тип модели **не** зависит от строкового пропа. Форму сериализации задаёт
отдельный проп `valueAdapter`, и она видна в типах:

| `valueAdapter` | Тип `modelValue` | Пример |
| --- | --- | --- |
| `'date'` (по умолчанию) | `Date \| null` | `new Date(2026, 7, 12)` |
| `'isoDate'` | `string \| null` | `'2026-08-12'` |
| `'isoDateTime'` | `string \| null` | `'2026-08-12T14:30:00'` |
| `'timestamp'` | `number \| null` | `1786_000_000_000` |
| свой `GrChronoAdapter<T>` | `T \| null` | пара `parse`/`serialize` |

У `GrDateRangePicker` адаптер применяется к **каждой границе**, поэтому модель —
пара: `['2026-08-10', '2026-08-14']` при `valueAdapter="isoDate"`.

### Свой адаптер

```ts
import type { GrChronoAdapter } from '@feugene/granularity-chrono'

const secondsAdapter: GrChronoAdapter<number | null> = {
  parse: raw => (typeof raw === 'number' ? new Date(raw * 1000) : null),
  serialize: date => Math.floor(date.getTime() / 1000),
}
```

`parse` обязан вернуть `null` на невалидном входе, а не бросить: значение
приходит из внешнего мира, и рендер не имеет права падать из-за него. Пакет
поступает так же — `'2026-02-31'` не разбирается, потому что не переживает
обратную сборку.

### Что означает «локальная полночь»

Дата без времени собирается как локальная полночь: пользователь выбирает день в
своём календаре, а не момент на мировой линии. `isoDateTime` тоже без смещения —
он описывает то, что человек видит на часах. Кому нужен момент, тот сериализует
`Date` сам своим адаптером.

## Публичная арифметика

Модули пакета экспортируются наружу: потребителю, которому нужно «плюс месяц»
или «попадает ли в диапазон», не нужно ставить date-библиотеку рядом с пакетом,
где это уже есть.

```ts
import { addMonths, isoWeekNumber, plainDate } from '@feugene/granularity-chrono'

addMonths(plainDate(2026, 0, 31), 1) // { y: 2026, m: 1, d: 28 } — день зажат длиной месяца
isoWeekNumber({ y: 2026, m: 11, d: 31 }) // неделя принадлежит году своего четверга
```

Там же — сетка месяца (`buildCalendarGrid`), колонки времени (`buildTimeColumns`),
обёртки `Intl` с кэшем (`formatPlainDate`, `weekdayNames`, `dayPeriodNames`) и
разбор набранного руками (`parseLocaleDate`, `maskLocaleDate`).

## Часы

Часы среды пакет читает в одном месте — `clockDate()`. Компонент зовёт её один
раз на экземпляр, а не при каждой перерисовке. Всё, что зависит от «сегодня»,
можно задать пропом `today` — и нужно задавать, если рендер обязан быть
детерминированным: в тестах, в снимках и при SSR (см. [`ssr.md`](./ssr.md)).
