# Значение: `Date` снаружи, кортежи внутри

## Почему так

Внутри пакета нет ни одного вычисления по `Date`. Даты считаются на кортежах
`{ y, m, d }`, время — на `{ h, min, s }`, и `Date` появляется ровно на границе:
при разборе `modelValue` и при отдаче значения наружу.

Причина не в эстетике. Арифметика по `Date` — `setDate(d + 1)`, `+ 86_400_000` — ломается в день перевода часов: сутки
там не равны 24 часам, «следующая неделя» уезжает на час, а на границе месяца — на день. Кортеж от этого свободен по
построению: перенос месяцев считается через `y * 12 + m`, длина месяца — таблицей с проверкой високосности. Тесты пакета
гоняются в зоне с переводом часов (`America/New_York`), где обе границы 2026 года попадают в проверки.

Второе следствие: `date-fns` и подобные пакету не нужны. Всё локале-зависимое — первый день недели, названия месяцев и
дней, 12/24-часовой вид, порядок частей при разборе — даёт `Intl`.

## Модель компонента

```ts
type GrChronoValue = Date | null
type GrChronoRangeValue = readonly [Date, Date] | null
```

Тип модели **не** зависит от строкового пропа. Форму сериализации задаёт отдельный проп `valueAdapter`, и она видна в
типах:

| `valueAdapter`            | Тип `modelValue` | Пример                   |
|---------------------------|------------------|--------------------------|
| `'date'` (по умолчанию)   | `Date \| null`   | `new Date(2026, 7, 12)`  |
| `'isoDate'`               | `string \| null` | `'2026-08-12'`           |
| `'isoDateTime'`           | `string \| null` | `'2026-08-12T14:30:00'`  |
| `'timestamp'`             | `number \| null` | `1786_000_000_000`       |
| свой `GrChronoAdapter<T>` | `T \| null`      | пара `parse`/`serialize` |

У `GrDateRangePicker` адаптер применяется к **каждой границе**, поэтому модель — пара: `['2026-08-10', '2026-08-14']`
при `valueAdapter="isoDate"`.

### Свой адаптер

```ts
import type {GrChronoAdapter} from '@feugene/granularity-chrono'

const secondsAdapter: GrChronoAdapter<number | null> = {
    parse: raw => (typeof raw === 'number' ? new Date(raw * 1000) : null),
    serialize: date => Math.floor(date.getTime() / 1000),
}
```

`parse` обязан вернуть `null` на невалидном входе, а не бросить: значение приходит из внешнего мира, и рендер не имеет
права падать из-за него. Пакет поступает так же — `'2026-02-31'` не разбирается, потому что не переживает обратную
сборку.

### Что означает «локальная полночь»

Дата без времени собирается как локальная полночь: пользователь выбирает день в своём календаре, а не момент на мировой
линии. `isoDateTime` тоже без смещения — он описывает то, что человек видит на часах. Кому нужен момент, тот сериализует
`Date` сам своим адаптером.

## Публичная арифметика

Модули пакета экспортируются наружу: потребителю, которому нужно «плюс месяц» или «попадает ли в диапазон», не нужно
ставить date-библиотеку рядом с пакетом, где это уже есть.

```ts
import {addMonths, isoWeekNumber, plainDate} from '@feugene/granularity-chrono'

addMonths(plainDate(2026, 0, 31), 1) // { y: 2026, m: 1, d: 28 } — день зажат длиной месяца
isoWeekNumber({y: 2026, m: 11, d: 31}) // неделя принадлежит году своего четверга
```

Там же — сетка месяца (`buildCalendarGrid`), колонки времени (`buildTimeColumns`), обёртки `Intl` с кэшем
(`formatPlainDate`, `weekdayNames`, `dayPeriodNames`), разбор набранного руками (`parseLocaleDate`, `maskLocaleDate`) и
разрыв между моментами (`selectRelativeAmount`, `formatRelativeTime`).

`differenceInMonths` считает **полные** месяцы: с 31 января по 28 февраля прошёл ноль месяцев, хотя индексы месяцев
различаются на единицу. Делить дни на 30 для этого нельзя — февраль и июль тогда одинаковы, и «месяц назад» уезжает на
неделю.

## Относительное время

`GrRelativeTime` («3 минуты назад») выбирает единицу **в двух режимах**, и это главное решение модуля:

| Разрыв   | Чем меряется                                                       |
|----------|--------------------------------------------------------------------|
| До суток | Прошедшим временем: секунда есть секунда, календарь тут ни при чём |
| От суток | Календарными кортежами: дни, недели, полные месяцы и годы          |

Отсюда два следствия, которые видно только на границах. Месяц остаётся месяцем и в феврале, и в июле — потому что
считается календарём. А сутки, длившиеся из-за перевода часов 23 часа, называются часами — потому что столько времени и
правда прошло; иначе двухчасовой разрыв через полночь каждую ночь назывался бы вчерашним.

Живой показ требует общего «сейчас»: `useChronoNow(interval)` держит **один таймер на такт**, а не на компонент, и
снимает его на скрытой вкладке. Такт задаёт вызывающий; `0` означает «не тикать». `GrRelativeTime` выбирает такт сам по
текущей единице — секунды пересчитываются раз в пять секунд, месяцы раз в час, — поэтому лента из ста меток стоит одного
`setInterval`.

```ts
import {selectRelativeAmount, useChronoNow} from '@feugene/granularity-chrono'

const now = useChronoNow(30_000)
selectRelativeAmount(now.value, posted) // { value: -3, unit: 'minute' }
```

## Строки интерфейса

В словарях пакета — только то, чего не знает платформа: подписи кнопок,
`aria-label`, заголовки панелей. Названия месяцев и дней недели, первый день недели, 12/24 часа и порядок частей при
разборе даёт `Intl`, поэтому язык интерфейса и язык дат — **две разные настройки**:

| Что                                              | Откуда берётся                                      |
|--------------------------------------------------|-----------------------------------------------------|
| «Предыдущий месяц», «Применить», «Выбор времени» | Словарь пакета через адаптер i18n приложения        |
| `август 2026 г.`, `пн вт ср`, `12.08.2026`       | `Intl` по пропу `locale` (не задан — язык адаптера) |

Отсюда следствие, которое видно только вживую: без подключённого словаря сетка переведётся, а подписи стрелок — нет. Как
подключить, показано в README пакета; блок у пакета свой (`grChrono`), потому что `gr` принадлежит ядру.

## Часы

Часы среды пакет читает в одном месте — `clockDate()`. Компонент зовёт её один раз на экземпляр, а не при каждой
перерисовке. Всё, что зависит от «сегодня», можно задать пропом `today` — и нужно задавать, если рендер обязан быть
детерминированным: в тестах, в снимках и при SSR (см. [`ssr.md`](./ssr.md)).
