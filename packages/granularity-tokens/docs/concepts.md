# Тема и режим: понятия

Дизайн-система различает два слова, которые в обиходе путают:

- **тема** — дизайн-язык целиком: полный набор значений одних и тех же токенов. Выбирается **на
  сборке**, в CSS приложения едет одна;
- **режим** — вариант внутри темы: те же примитивы, другие роли (`light`, `dark` или свой).
  Набор режимов тоже задаётся на сборке, а переключается между ними — **в рантайме**: все режимы
  сборки уже лежат в CSS.

Имена токенов у всех тем одни и те же — их задаёт реестр пакета. Поэтому компоненты о темах не
знают: они ссылаются на `--gr-primary`, а значение роли приходит из темы и режима.

Здесь — что такое тема и режим, из чего они состоят и как связаны. Как переключать режим в
приложении — [`modes.md`](../../granularity/docs/modes.md) ядра; как собрать свой режим или свою
тему — [`themes.md`](./themes.md); какие токены есть — [`tokens.md`](./tokens.md).

## Коротко

| | Тема | Режим |
| --- | --- | --- |
| Что это | дизайн-язык: примитивы, роли каждого режима, правила | вариант темы: роли и тени поверх общих примитивов |
| Что решает сборка | какие темы есть — `themes` конфига granum, одна из них основная | какие режимы есть у каждой темы — `modes` её записи |
| Что решает рантайм | какая тема сейчас — `useTheme().setTheme()` | какой режим сейчас — `useTheme().setMode()` |
| Сколько в CSS | основная — в общем листе, каждая дополнительная — своим листом | режимы набора темы; по умолчанию один — режим по умолчанию темы (`light`) |
| Где хранится выбор | вместе с режимом: `<тема>-<режим>` у дополнительной темы | имя режима в `localStorage` (`gr-theme`) или cookie |
| Чем включается | без атрибута — основная; иначе парой | парой `data-theme="<тема>-<режим>"` на корне или поддереве |
| Пример | `slate` («Сланец») | `light`, `dark`, `ocean` поверх `dark` |

## Тема

Тема отвечает на вопрос «как выглядит дизайн-система»: какие скругления, шрифты и отступы, какой
акцент и какие нейтрали, как они ведут себя в светлом и тёмном виде, какие правила нельзя
выразить токеном. Две темы — это два разных продукта на одних и тех же компонентах.

### Из чего состоит

Встроенная тема лежит папкой `themes/<id>/` пакета; своя тема приложения — папкой той же
раскладки.

| Часть | Где | Что внутри | От режима |
| --- | --- | --- | --- |
| Метаданные | `theme.json` | `id`, название, описание, `docs` (страница темы), `extends`, режим по умолчанию, список режимов с названием и `colorScheme` | — |
| Примитивы | `root.json` | палитра, шрифты, шкалы кегля, отступов и радиусов, движение, слои | не зависят |
| Режимы | `modes/<режим>.json` | роли (поверхности, текст, действия, статусы, сплошные заливки, данные, навигация) и тени | по режиму |
| Производные состояния | реестр пакета | `-hover`, `-active` и соседи — формулы `color-mix` от ролей; тема их не объявляет | по режиму, сами |
| Фолбэки | собирает пакет | производные, посчитанные в hex, — для браузеров без `color-mix` | по режиму |
| Токены компонентов | `components/<Имя>/themes/<id>/` у компонента | значения собственных переменных компонента для этой темы: `root.json` и `modes/<режим>.json` | частично |
| Пропсы по умолчанию | `componentDefaults` в `theme.json` | то, что токеном не выразить: вид индикатора загрузки, форма группы кнопок | не зависят |
| Пояснения | `notes.json`, `README.md` | почему значение такое; для чего тема, правила использования, ссылка на её страницу | — |

Практическое правило: меняется при переключении режима → роль режима; одинаково всегда →
примитив; выводится из роли → производное, его не объявляют.

Токены компонентов лежат у компонентов, а не в папке темы: тема их не знает, сборка собирает их
для каждой темы сборки сама. Поэтому новая тема не обязана повторять переменные `GrButton`: без своих
значений компонент берёт их по цепочке `extends` тем — у темы, наследующей `slate`, из `slate`.

### Каталог, наследование, темы сборки

- **Каталог** — список встроенных тем: `grThemeCatalog` (id, название, режимы, без значений).
  Владелец каталога в сборке один — этот пакет; ядро и спутники — потребители его тем.
- **Наследование** — тема может наследовать тему каталога (`"extends": "slate"`) и объявлять
  только отличия: свой акцент, свои радиусы. Режим может наследовать режим той же темы.
- **Темы сборки** — темы, перечисленные в `themes` конфига granum (без ключа — одна `slate`).
  Остальные темы каталога в сборку не попадают и не читаются.
- **Основная тема** — единственная тема сборки или помеченная `default: true`. Её блоки лежат в
  общем листе, а режим по умолчанию — ещё и на `:root`, поэтому страница без атрибута уже
  оформлена.
- **Дополнительная тема** — любая другая тема сборки: свой лист с полными блоками её пар, под
  `:root` она не выходит никогда. Лист грузится по требованию — `useTheme().setTheme('clay')` или
  остров `<GrConfigProvider theme="clay">` берут его адрес из манифеста, — поэтому странице,
  которая тему не показывает, она ничего не стоит. Странице, которая показывает её всегда, лист
  импортируется статически: `virtual:granum/themes/clay.css`.

## Режим

Режим отвечает на вопрос «в каком виде показать ту же дизайн-систему сейчас»: светлом, тёмном,
приглушённом, высококонтрастном. Шрифты, радиусы и отступы у режимов одной темы общие — меняются
роли и тени.

### Что есть у режима

- **имя** — `^[a-z][a-z0-9]*$`, без дефиса и не `root`: дефис отделяет тему от режима в паре;
- **название** — для переключателя («Тёмный»);
- **`colorScheme`** — `light` или `dark`. Сборка объявляет по нему `color-scheme` в блоке режима
  (нативные скроллбары, поля, `<select>`); по нему выбирается режим, когда приложение следует
  системной схеме; по нему считается `isDark` и переключает `toggleMode()`;
- **токены** — роли и тени; при `extends` — только отличия от режима-предка;
- **`extends`** — режим той же темы, от которого он наследует (`dim` поверх `dark`).

### Режим по умолчанию и набор режимов

- **Режим по умолчанию** — `defaultMode` темы (у `slate` — `light`). У основной темы его блок лежит
  ещё и под `:root`; скрипт до первого кадра и контроллер берут его, когда нет ни сохранённого
  выбора, ни режима подходящей системной схемы, а `setTheme` — когда у новой темы нет ни
  одноимённого режима, ни режима той же схемы.
- **Набор режимов темы в сборке** — режимы, перечисленные в `modes` её записи `themes` (массивом
  имён или `modes.names`). Без них в сборку попадает только режим по умолчанию темы (`light`) и
  режимы приложения из `modes.define`: тема собирается под приложение, и второй режим — его
  решение, а не умолчание. У каждой темы сборки набор свой. Режим, от которого наследует режим
  набора (`ocean` от `dark`), сам в набор входить не обязан: значения берутся по цепочке, блока у
  него нет. В CSS — глобально и у компонентов — попадают только режимы набора.
- **Режим приложения** — `modes.define` записи темы: режим поверх режима этой темы
  (`{ extends: 'dark', tokens }`) со своим именем, названием и `colorScheme`. Для приложения он ничем не отличается от режима
  темы: та же пара, тот же `setMode()`.
- **Точечная правка** — `modes.tokenOverrides`: значение для `root` или для режима набора без
  нового режима.

Значение токена в режиме собирается из слоёв, каждый следующий перекрывает предыдущий: данные
темы (`root`, затем цепочка режима) → токены компонентов для темы → тема-объект приложения →
`modes.define` → `modes.tokenOverrides`. Токен, объявленный хоть в одном режиме, получает значение
в каждом: по цепочке `extends`, иначе из режима по умолчанию.

### Пара: как режим включается

Пара — имя темы и режима через дефис в атрибуте корня: `data-theme="slate-dark"`.

- **Почему пара, а не имя.** На одной странице могут стоять пары разных тем — документа и острова, —
  а имя режима у них одно. Селектор `[data-theme="dark"]` не совпадёт ни с одним блоком CSS.
- **Атрибут и шаблон** задаёт `activation` конфига, общий на все темы сборки: по умолчанию
  `data-theme` и `{theme}-{mode}`.
- **Пару не пишут руками.** Её отдаёт манифест сборки `virtual:granum/themes`: `useTheme`,
  контроллер granum, `themeModeValue`, скрипт до первого кадра берут пары оттуда.
- **Хранится ключ выбора, ставится пара.** У основной темы в `gr-theme` лежит `dark`, на корне —
  `slate-dark`: смена основной темы на сборке не сбрасывает выбор пользователя. Выбор
  дополнительной темы хранится как `<тема>-<режим>` (`clay-dark`).

### Где режим действует

- **Документ** — пара на `<html>`: её ставят `useTheme().setMode()` и `setTheme()`, контроллер
  granum и инлайн-скрипт в `<head>` до первого кадра.
- **Остров** — пара на поддереве: `<GrConfigProvider mode="dark">`, другой темы —
  `<GrConfigProvider theme="clay" mode="dark">`. Формулы ролей пересчитываются
  от ролей острова, панели, улетающие в `body`, берут режим своего хозяина.

### Чем режим не является

- **Не тема.** Нужны другие шрифты, радиусы или другой характер — это тема, а не режим.
- **Не класс.** Классов `.light` и `.dark` нет; свой CSS под режим пишется ролями `--gr-*`,
  вариантом `dark:`, `light-dark()` или суффиксом пары — порядок выбора в
  [`modes.md`](../../granularity/docs/modes.md#свой-css-под-режим) ядра.
- **Не проп `dark`.** `dark` у `GrBadge` и `GrChip` — вариант заливки компонента, он работает в
  любом режиме.

## Словарь

| Понятие | Что значит |
| --- | --- |
| Тема | дизайн-язык целиком: примитивы, роли каждого режима, правила |
| Режим | вариант темы: роли и тени поверх общих примитивов; переключается в рантайме |
| Пара | `<тема>-<режим>` в атрибуте активации: `data-theme="slate-dark"` |
| Тема сборки | тема из `themes` конфига granum; остальные темы каталога в CSS не попадают |
| Основная тема | тема сборки в общем листе; её режим по умолчанию лежит на `:root` |
| Дополнительная тема | тема сборки своим листом, только под своими парами; лист грузится по требованию |
| Режим по умолчанию | режим, действующий без атрибута и без выбора пользователя |
| Режим приложения | `modes.define` записи темы: режим поверх режима темы, объявленный в конфиге приложения |
| Каталог | список встроенных тем пакета: `grThemeCatalog` |
| Реестр | имена и смысл токенов без значений: `grFoundationTokens`, `grRoleTokens`, `grDerivedTokens` |
| Примитив | токен, одинаковый во всех режимах темы: отступ, радиус, шрифт |
| Роль | семантический токен, который меняется с режимом: `--gr-bg`, `--gr-primary-text` |
| Производное состояние | токен, выведенный формулой от роли: `--gr-primary-hover` |
| Фолбэк | значение производного в hex для браузеров без `color-mix` |
| Токены компонента по теме | значения собственных переменных компонента для темы: `components/<Имя>/themes/<id>/` |
| Пропсы по умолчанию темы | `componentDefaults` темы: слой ниже приложения, провайдера и локального пропа |
| Остров | поддерево с собственной парой: `<GrConfigProvider mode>` или `<GrConfigProvider theme mode>` |
| Манифест тем | `virtual:granum/themes`: темы сборки, их режимы, пары, адреса листов, основная тема и атрибут — из той же сборки, что CSS |

## Смежное

- [`modes.md`](../../granularity/docs/modes.md) ядра — переключение, острова, SSR, свои режимы в
  конфиге, токены компонентов по темам;
- [`themes.md`](./themes.md) — что тема обязана объявить, суффиксы ролей, свой режим и своя тема,
  проверка перед выкладкой;
- [`tokens.md`](./tokens.md) — все глобальные токены со значениями по режимам;
- [`themes/README.md`](../themes/README.md) — каталог и раскладка папки темы.
