# Контракт форм-контрола

Шестнадцать компонентов пакета — форм-контролы: от `GrInput` до `GrFileUpload`. Контракт
существует ради одного: чтобы обёртка, написанная над одним из них, работала над любым.

| Часть | Что входит | Чем держится |
| --- | --- | --- |
| Пропы | `disabled`, `readonly`, `invalid`, `required`, `ariaLabel` | `useGrFormControl(() => props)` |
| Методы | `focus()`, `blur()` | `defineExpose` |
| События | `update:modelValue`, `change`, `focus`, `blur`, `clear` | — |

Все три части проверяет `src/__tests__/formControlContract.test.ts` — по отрендеренному DOM и
публичной поверхности компонента, а не по факту вызова композабла.

## Пропы

`useGrFormControl` сводит собственные пропы контрола с контекстом `GrFormField` по правилу
«или», а не `??`: пропы объявлены с дефолтом `false`, и `??` до контекста не дошёл бы — поле
не смогло бы включить `readonly` всей форме.

Проп обязан быть **объявлен**, а не оставлен на fallthrough: необъявленный протекает на
корень и в разметке выглядит реализованным. `ariaLabel` Vue вдобавок сама нормализует в
`aria-label`, и на глаз такой контрол неотличим от настоящего.

## События

```vue
<GrAnyControl
  v-model="value"
  @change="onCommit"
  @focus="onFocus"
  @blur="onBlur"
  @clear="onClear"
/>
```

- `update:modelValue` — значение изменилось;
- `change` — значение **зафиксировано** пользователем. У текстовых полей это `change` DOM'а,
  у остальных совпадает с моментом `update:modelValue`;
- `focus` / `blur` — контрол получил и потерял фокус;
- `clear` — значение снято кнопкой очистки. Объявлен у всех, у кого есть проп `clearable`.
  Обратное неверно: `GrFormFile` очищается всегда, когда файл выбран, и выключателя у него
  нет.

`clear` нужен отдельно от `update:modelValue`: по пустому значению потребитель не отличит
очистку от честного «пусто», а это разные события для аналитики и для валидации.

### Составные контролы и граница фокуса

У группы (`GrRadioGroup`, `GrSegmented`, `GrCheckboxGroup`, диапазонный `GrSlider`,
`GrInputTag`, файловые зоны) фокус ходит **внутри**: между радиокнопками, между чипом и полем,
между двумя бегунками. Нативные `focus`/`blur` при этом не всплывают вовсе, а `focusin`/
`focusout` всплывают на каждый такой переход.

Контрол эмитит `focus`/`blur`, только когда фокус пересёк его границу. Стрелка, переводящая
фокус с одного пункта на соседний, событий не порождает — иначе обёртка получала бы пару
`blur` + `focus` на каждое нажатие. Правило живёт в `composables/internal/useFocusWithin.ts`.

У комбобоксов (`GrSelect`, `GrAutocomplete`, `GrTreeSelect`) частью контрола считается и
телепортированная панель: она лежит вне корня, но уход фокуса в её поле фильтра — не `blur`.

### Почему события разводятся руками

Объявленный emit **уходит из `$attrs`**. Пока события нет в `defineEmits`, нативное просто
протекает на корень, и `@focus` у потребителя работает само собой. Объяви его и не разведи —
и `@focus` молча перестанет работать у всех, кто его уже слушает.

Поэтому у каждого контрола событие привязано к тому же элементу, на который попадало раньше.
Гейт `src/__tests__/formControlEvents.test.ts` проверяет именно это — что событие доходит на
живом взаимодействии, а не только объявлено.

## Слоты

Слот — это **роль**, а не место в разметке. Одна роль во всём пакете зовётся одним именем:
иначе потребитель, перешедший с одного контрола на другой, переписывает шаблон из-за того,
что «подвал» здесь `foot`, а там `footer`.

### Общий словарь

| Роль | Что кладут |
| --- | --- |
| `default` | основное содержимое: подпись флажка, свои `<option>`, своя зона загрузки |
| `prefix` / `suffix` | аддон в поле: знак валюты, единица измерения, иконка |
| `header` / `footer` | шапка и подвал блока |
| `title` / `description` / `label` | заголовок, пояснение под ним, подпись контрола |
| `icon` | иконка перед содержимым |
| `error` | вывод ошибки вместо стандартного |
| `empty` / `loading` | состояния списка: пусто и данные в пути |
| `actions` | кнопки, относящиеся ко всему блоку |
| `trigger` / `content` | у оверлеев: то, за что открывают, и то, что открывается |

Всё остальное — **доменные** роли: они осмысленны только у своего компонента (`option`
у `GrSelect` и `GrAutocomplete`, `tag` у `GrInputTag`, `symbol` и `text` у `GrRating`,
`node` и `value` у `GrTreeSelect`). Владелец объявлен явно в гейте
`src/__tests__/slotContract.test.ts`; чужой компонент то же имя занять не может.

Правило простое: **нет роли — нет слота**. Слот заводится, когда потребителю нужно заменить
содержимое, а не «на всякий случай».

### Аддоны `prefix` / `suffix`

Есть у контролов с текстовой оболочкой: `GrInput`, `GrNumberInput`, `GrAutocomplete`,
`GrTreeSelect`, `GrInputTag` и `GrSelect` в режиме `optionsView="panel"` (внутрь нативного
`<select>` разметку положить нельзя — в dev об этом предупредит консоль).

```vue
<GrNumberInput v-model="amount">
  <template #prefix>₽</template>
  <template #suffix>за кг</template>
</GrNumberInput>
```

Аддон **резервирует место, а не заменяет отступ**: поле с аддоном и без него одинаково отбито
от края. Ширина берётся по факту (`ResizeObserver`) в границах шести пропов:

| Проп | Что делает |
| --- | --- |
| `prefixMinWidth` / `suffixMinWidth` | нижняя граница; по умолчанию — ширина аддона для ступени размера |
| `prefixMaxWidth` / `suffixMaxWidth` | верхняя граница; содержимое шире — обрезается |
| `prefixFixed` / `suffixFixed` | жёсткая ширина (`*MaxWidth` → `*MinWidth` → дефолт) |

`*Fixed` нужен, когда аддоны соседних полей обязаны совпасть по ширине: без него каждое поле
меряет свой аддон, и колонка «плывёт».

Механизм один на все контролы — `composables/internal/useControlAddons.ts`. Новый контрол с
текстовой оболочкой зовёт его, а не пишет свою математику паддингов.

### Типы

Слоты объявляются через `defineSlots` — иначе они не попадают в `.d.ts`, и потребитель узнаёт
имя слота из исходников компонента. Scoped-слоты объявляют и типы своих пропов:

```ts
defineSlots<{
  prefix?: () => any
  option?: (props: { option: GrSelectOption<TValue>, selected: boolean }) => any
}>()
```
