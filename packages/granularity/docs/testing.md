# Тестовые утилиты

`@feugene/granularity/testing` — набор помощников для тестов, где живут
компоненты пакета. Раннер и способ монтирования выбираете вы: точка входа не
зависит ни от `vitest`, ни от `@vue/test-utils` и отдаёт только данные и
действия над DOM.

## Указательные жесты

```ts
import { cancelPointer, drag, move, press, release } from '@feugene/granularity/testing'

press(handle, { clientY: 10 }) // нажатие — в элемент
move({ clientY: 60 }) // движение и отпускание — в window
release()

drag(handle, { clientY: 10 }, { clientY: 60 }) // то же одной строкой
cancelPointer() // обрыв: система забрала указатель
```

Две ловушки, ради которых это не пишется руками.

**Движение и отпускание слушает `window`, а не элемент.** Так устроен
`useDragGesture`, а с ним слайдер, сплиттер, перестановка списка и колонок,
смахивание тоста: нажатие приходит от разметки, дальше жест ведётся глобально —
иначе он обрывался бы на выходе курсора за элемент. Тест, отправивший
`pointermove` в тот же элемент, не проверяет ничего и делает это молча.

**`wrapper.trigger('pointerdown', { clientY })` падает.** `@vue/test-utils`
создаёт настоящее событие и присваивает ему ключи опций, а координаты у
`MouseEvent` и `PointerEvent` — только геттеры: `TypeError: Cannot set property
clientY of #<MouseEvent> which has only a getter`. Помощники передают координаты
в конструктор (`MouseEvent`: жестам пакета нужны координаты и кнопка, а не
`pointerId`) и отправляют событие `dispatchEvent`-ом; `button: 0` подставляется по
умолчанию, потому что неосновную кнопку жест игнорирует.

`cancelPointer` проверяет отдельную ветку поведения: обрыв **возвращает**
состояние, а не дожимает жест — тост уезжает назад, порядок откатывается.

## Клавиатура и IME

```ts
import { composingKeydown, keydown } from '@feugene/granularity/testing'

keydown(input, 'Enter') // обычное нажатие
composingKeydown(input, 'Enter') // то же во время IME-композиции
```

`composingKeydown` ставит **оба** признака композиции: `isComposing: true` и
`keyCode: 229`. Пакет читает композицию предикатом `event.isComposing ||
event.keyCode === 229`, потому что Safari до 16.4 не выставлял первое, — и тест,
задавший один флаг, проверяет половину предиката. Второе, что даёт помощник, —
имя: вызов `composingKeydown` говорит, что проверяется именно композиция, а не
обычный Enter с лишним полем в объекте. `wrapper.trigger('keydown', { isComposing:
true, keyCode: 229 })` доставляет то же самое, если писать оба флага руками.

Зачем это вообще: пока идёт набор через IME, `Enter` подтверждает выбор
иероглифа, а не действие виджета. Контрол, который на нём выберет опцию или
отправит форму, у такого пользователя неработоспособен — он не введёт ни одного
слова, не совершив случайного действия.

## Геометрия

```ts
import { mockRect, stackRects } from '@feugene/granularity/testing'

mockRect(track, { width: 200 }) // недостающие стороны выводятся из заданных
stackRects(rows, { size: 20 }) // строки встык по вертикали
stackRects(headerCells, { size: 100, axis: 'horizontal', cross: 40 })
```

Раскладки в jsdom нет: `getBoundingClientRect` всегда нулевой. Всё, что считает
попадание указателя или измеряет соседей — шкала слайдера, строки перестановки,
ширины колонок, смещения закреплённых колонок, — на нулевом прямоугольнике не
проверяется.

## Окружение пакета

```ts
import { granularityGlobal } from '@feugene/granularity/testing'

mount(GrSelect, { props, global: granularityGlobal({ size: 'sm' }) })

mount(GrButton, {
  global: granularityGlobal({
    componentDefaults: { GrButton: { variant: 'outline' } },
    i18n: { 'gr.select.loading': 'Гружу…' }, // словарь, адаптер или опции
  }),
})
```

Помощник раздаёт то же, что `<GrConfigProvider>` кладёт в `provide`: конфиг
компонентов и адаптер перевода. Проверять **сам** провайдер (его разметку, тему
на корне) этим нельзя — для этого его и монтируют.

Адаптер отдельно доступен как `i18nAdapter({ t, te, locale })`; без словаря он
возвращает сам ключ, и в разметке видно, о чём компонент спросил.

## Живой регион

```ts
import { announced } from '@feugene/granularity/testing'

await grid.get('[data-day="2026-08-13"]').trigger('click')
expect(await announced()).toBe('13 августа 2026')
```

Ждать здесь обязательно: `announce` пишет в регион отложенным макротаском, и это
условие работы, а не деталь. Регион, в котором текст появился в том же кадре,
что и сам регион, часть скринридеров не объявляет вовсе. `announced('assertive')`
читает срочный регион.

## Уборка

```ts
import { resetGranularityDom } from '@feugene/granularity/testing'

afterEach(resetGranularityDom)
```

Снимает очередь тостов, таймеры и хост живого региона, корень портала, очередь
сервиса диалогов вместе с захваченным контекстом приложения и содержимое `body`.
Одного `document.body.innerHTML = ''` мало: узлы уходят, а модульное состояние
пакета переживает тест. Неотвеченный диалог прошлого теста стоит головой очереди,
и новый не появляется вовсе; диалог, открытый вне `setup`, берёт словарь,
захваченный прошлым тестом, — и всё это без единой ошибки в консоли.

Приложения Vue помощник **не размонтирует**: это работа раннера.
Размонтированный не вовремя слой остаётся в стеке Esc и `inert` и держит
блокировку прокрутки, поэтому вместе с уборкой включите автоматическое
размонтирование `@vue/test-utils`:

```ts
import { enableAutoUnmount } from '@vue/test-utils'

enableAutoUnmount(afterEach)
afterEach(resetGranularityDom)
```

## Заглушка `matchMedia`

```ts
import { stubMatchMedia } from '@feugene/granularity/testing'

const restore = stubMatchMedia({ reducedMotion: true })
// …проверяем, что анимации нет
restore()
```

Нужна только чтобы **задать ответ**: сам по себе `matchMedia` пакет вызывает
опционально и без него не падает. Возвращается функция отката — глобальное
состояние должно уходить вместе с тестом.

## Чего здесь нет

Обёрток над раннером (фейковые таймеры, моки функций) и над способом
монтирования. Это API вашего инструмента: пакет не должен решать за вас, чем вы
тестируете, и не должен ломаться от смены его мажорной версии.

Нет и того, что про тесты компонента, но **не про дизайн-систему**: бросающий
`queryOne`, прототипная подмена прямоугольника, кадр `requestAnimationFrame`,
axe в jsdom, клавиатурный обход в Playwright. Всё это живёт в
`@feugene/granularity-test-kit` — подпутями `./vue`, `./a11y` и `./e2e`.

Граница проходит по знанию о пакете, а не по слову «тест»: всё в этом модуле
тестовое, но `granularityGlobal`, `announced` и `resetGranularityDom` ходят во
внутренности ядра — в реестр конфига, объявитель и корень портала. Уедь они в
тест-кит, он стал бы зависеть от ядра, а ядро зовёт его фабрики: зависимость
замкнулась бы в цикл. У остальных такой привязки нет, и держать их здесь значило
бы требовать peer на ядро от того, кому нужен один хелпер.

Пара прямоугольников разведена по этой же линии и об этом стоит знать заранее:
`mockRect` вешает размер на **известный** элемент и остаётся здесь, а
`stubElementRects` подменяет прототип — он нужен, когда компонент меряет свой
корень в `onMounted`, то есть раньше, чем тест до узла доберётся.
