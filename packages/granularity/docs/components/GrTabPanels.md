# GrTabPanels

Контейнер `tabpanel`-ов, companion к [`GrTabs`](./GrTabs.md): показывает панель
активной вкладки и связывает её с вкладкой по ARIA.

## Когда брать

- **к вкладкам нужны панели** — компонент связывает их с `GrTabs` по ARIA, без ручных `id`;
- **панель тяжёлая** — ленивое монтирование не строит содержимое до первого показа;
- **состояние панели надо сохранить** — скрытая панель остаётся смонтированной, и введённое в ней не пропадает;
- **раскладка вкладок своя** — панели стоят отдельно от списка вкладок, а не под ним.

## Когда взять другое

| Нужно | Берите |
| --- | --- |
| Нужен сам список вкладок | [`GrTabs`](./GrTabs.md) |
| Разделы раскрываются, а не переключаются | [`GrCollapse`](./GrCollapse.md) |
| Переключается вид одного содержимого | [`GrSegmented`](./GrSegmented.md) |

## Связка держится на общем `idBase`

```vue
<GrTabs v-model="tab" :tabs="tabs" id-base="settings" />

<GrTabPanels v-model="tab" id-base="settings">
  <GrTabPanel value="profile">…</GrTabPanel>
  <GrTabPanel value="billing">…</GrTabPanel>
</GrTabPanels>
```

`idBase` реактивен: его изменение доезжает до панелей. Раньше он вычислялся
один раз при setup — панели оставались со старыми id, `GrTabs` уезжал на новые,
и `aria-controls` ↔ `aria-labelledby` разъезжались молча.

Без `idBase` он генерируется сам — на собственный id панели этого хватает, а вот
связи с вкладкой не будет: `GrTabs` проставляет вкладкам id **только** при явном
`idBase`. В этом случае панель `aria-labelledby` не выставляет вовсе. Ссылка в
пустоту хуже её отсутствия: диктор объявил бы имя панели пустой строкой вместо
«имени нет», и потребитель уже не смог бы это починить. В dev-сборке случай
выводится предупреждением — тем же приёмом, каким `GrFormField` ловит забытый
контрол.

## Смена панели

Входящая панель проявляется за `--gr-duration-fast`, слегка подъезжая снизу.
Уходящая исчезает мгновенно, и это не экономия: держи контейнер обе панели
разом, он на время перехода вырос бы на высоту обеих и дёрнул страницу.

При `keepAlive` перехода нет вовсе — панель из DOM не уходит, а `hidden` это
`display: none`, который не анимируется в принципе. Системная настройка
«уменьшить движение» гасит появление, как и всюду в пакете (`docs/motion.md`).

## `keepAlive` и `lazy`

По умолчанию неактивная панель не в DOM. `keepAlive` оставляет её скрытой
(`hidden`) — состояние форм не теряется. `lazy` добавляет к этому «не
монтировать, пока не показали впервые»: вместе они дают «смонтировать один раз
по требованию и больше не разрушать».

| `keepAlive` | `lazy` | Поведение |
| --- | --- | --- |
| — | — | панель монтируется при показе, размонтируется при уходе |
| ✓ | — | все панели в DOM сразу, неактивные скрыты |
| ✓ | ✓ | панель появляется в DOM при первом показе и остаётся |
