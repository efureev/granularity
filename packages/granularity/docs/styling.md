# Стилизация и темы

## Публичный CSS API пакета

Пакет `@feugene/granularity` публикует два уровня CSS-артефактов: общий бандл и
слои, из которых он собран.

- `@feugene/granularity/styles.css`
  - тема `slate` в обоих режимах (`light` и `dark`) с токенами компонентов ядра,
    базовые правила и reset — одним файлом;
  - для потребителя, который не подключает granum;
  - **utility-классов компонентов в нём нет**: их генерирует движок приложения по
    тем компонентам, которые выбраны. Без granum компонент получит токены и
    темы, но ни раскладочных утилит, ни собственного CSS — его тоже доставляет
    granum из манифеста.
- `@feugene/granularity/themes/<тема>/root.css` и `themes/<тема>/<режим>.css` —
  готовый CSS темы каталога по частям: в `root.css` всё, что от режима не зависит
  (примитивы, формулы, общие токены компонентов ядра), в файле режима — его пара
  с фолбэками `@supports`. Приложение подключает `root.css` и только свои режимы;
  бандлер склеит их в один файл. См. «Тема по частям» ниже.
- `@feugene/granularity/themes/<тема>.css` — та же тема целиком, склейка
  `root.css` и всех режимов каталога.
- `@feugene/granularity/styles/base.css` — базовые правила поверх темы:
  reset и кламп движения по `prefers-reduced-motion`.
- `@feugene/granularity/styles/preflight.css` — preflight-слой.

**Своего CSS-файла у компонента подключать не нужно.** У большинства компонентов
собственного CSS нет вовсе, а у тех, у кого есть (`GrIcon`, `GrToaster`,
`GrSplitter` и ещё восемнадцать), его `styles.css` granum берёт из манифеста
пакета в слой `granum.components`; JS-чанк компонента CSS не импортирует, поэтому
двойной доставки нет. Subpath вида
`@feugene/granularity/components/<Name>/styles.css` пакет не публикует —
такой файл был бы кусочком без токенов и тем, и подключать его отдельно
бессмысленно.

## Тема — данные, CSS собирает granum

Токенов и тем в виде CSS в исходниках пакета нет. Реестр токенов и значения темы
`slate` живут данными в `@feugene/granularity-tokens`, значения токенов
компонентов по темам — рядом с компонентами (`src/components/GrX/themes/slate/`,
поле `themesDir` в `config.ts`). Селекторы режимов назначает granum: режим
включается парой `data-theme="slate-<режим>"`, режим по умолчанию объявлен ещё и
на `:root`.

Что откуда берётся (пути — в `packages/granularity-tokens`):

| Источник | Что в нём |
| --- | --- |
| `tokens/{foundation,roles,derived}.json` | реестр: имена, группы, описания, формулы hover/active — без значений |
| `themes/slate/root.json` | примитивы: палитра, типографика, spacing, радиусы, motion, z-index |
| `themes/slate/modes/{light,dark}.json` | роли и тени режима |

Формулы производных — `color-mix`-объявления на корне и на каждом
`[data-theme]`; фолбэки для `@supports not (color-mix)` считает сборка темы той
же формулой.

Те же данные доступны как TS-справочник — `@feugene/granularity-tokens`
(`grFoundationTokens`, `grRoleTokens`, `grDerivedTokens`, каталог тем), значения —
`@feugene/granularity-tokens/themes/slate/theme.json`. У ядра в
`@feugene/granularity/tokens` — только реестр покомпонентных токенов. Ни то, ни
другое не входит в корневой бандл: это данные для доков и инструментов.
Человекочитаемая таблица — `docs/tokens.md` пакета токенов, тоже генерируемая.

Готовые файлы темы для подключения без granum собирает сборка пакета
(`scripts/theme-css.mjs`) через `emitThemeStylesheet` granum — по тем же правилам, что и
приложение на granum, поэтому
вычисленные значения у обоих путей совпадают: это сверяет
`yarn workspace @feugene/granularity themes:values:check` в Chromium.

### Тема по частям

```
themes/slate/root.css    всё, что от режима не зависит
themes/slate/light.css   :root и пара slate-light — режим по умолчанию
themes/slate/dark.css    пара slate-dark
themes/slate.css         склейка root.css и всех режимов
```

```ts
import '@feugene/granularity/themes/slate/root.css'
import '@feugene/granularity/themes/slate/dark.css'
```

- **`root.css` — первым.** Фолбэк режима заменяет формулу из `root.css` при
  равной специфичности, и выигрывает тот, кто ниже.
- **Режим самодостаточен.** Наследование по `extends` в нём раскрыто, токены
  компонентов — тоже: файлу режима не нужен ни файл базы, ни соседний режим. Это
  держит гейт `src/__tests__/themeParts.test.ts`: `root.css` и один режим дают
  элементу с парой те же значения, что тема целиком.
- **`:root` — только у режима по умолчанию** (у `slate` — `light.css`), и под
  `:where(:root)`, с нулевой специфичностью: пара любой темы на корне перекрывает его
  независимо от порядка листов. Приложение без него ставит пару на `<html>` само:
  `<html data-theme="slate-dark">` или скриптом режима.

Приложение на granum этих файлов не берёт: его сборка выпускает общий лист с основной темой и её
режимами из `themes` конфига (режим по умолчанию она сажает на `:root` сама) и по листу на каждую
дополнительную тему.

## Что объединяет эти файлы

`packages/granularity/src/styles/index.css` — source-группа foundation-стилей:

```css
@import '../themes/slate.css';
@import './base.css';
```

Она и уезжает в `dist/styles/index.css`, то есть в публичный
`@feugene/granularity/styles.css`. Порядок внутри `themes/slate.css` решает исход
при равной специфичности: примитивы и формулы, затем режимы, затем фолбэки
`@supports` — фолбэк обязан идти после формулы, которую он заменяет. Utility-классы
компонентов пакет не досбирает: их генерирует движок **на стороне приложения**,
по списку выбранных компонентов и по классам, которые сборка пакета записала в
манифест.

## Границы ответственности

### `styles.css`

Готовый foundation: тема `slate` в обоих режимах и base. Берите его,
если приложение не подключает granum, — тогда компоненты получат токены и темы,
но ни раскладочных утилит, ни собственного CSS: оба приезжают только через
granum.

Приложение на granum в этом файле обычно не нуждается: плагин отдаёт и
foundation, и утилиты выбранных компонентов одним `virtual:granum.css`, пятью
каскадными слоями.

### CSS самого компонента

Подключать нечего и не нужно. Собственный CSS есть у двадцати одного компонента
(`GrIcon`, `GrToaster`, `GrSplitter`, …): его `styles.css` granum берёт из
манифеста пакета в слой `granum.components`, а JS-чанк компонента CSS не
импортирует. У остальных своего CSS нет вовсе — они целиком
собираются из утилит, которые генерирует движок приложения.

Поэтому subpath `components/<Name>/styles.css` пакет не публикует: такой файл был
бы куском без токенов и тем, и подключать его отдельно бессмысленно.

### Низкоуровневые `styles/*`

Нижний уровень API для ручной композиции:

- `themes/slate/root.css` и `themes/slate/<режим>.css` (и любая другая тема каталога),
  целиком — `themes/<тема>.css`;
- `styles/base.css`;
- `styles/preflight.css`.

Полезны, если приложение собирает foundation само. Токенов спутников
(`@feugene/granularity-chrono` и других) в `themes/<тема>.css` нет: без granum их
собрать некому.

## Встроенные темы

Пакет берёт тему `slate` из каталога `@feugene/granularity-tokens` — режимы
`light` и `dark`, по умолчанию `light`. В приложении на granum тему выбирает
`theme`, режимы — `modes` конфига; без granum оба режима входят в `styles.css`.
Режим включается парой `data-theme="slate-dark"` на `<html>` или на острове.

## Граница ответственности: `tokens` vs `theme`

Практическое правило:

- если значение одинаково для разных тем — это `tokens`;
- если значение должно меняться при переключении темы — это `theme`.

Примеры:

- `--gr-space-4`, `--gr-radius-md`, `--gr-duration-fast` → `tokens`;
- `--bg`, `--primary`, `--brd`, `--ring` → `theme`;
- производные значения вроде `--primary-hover`, если они рассчитываются от semantic-переменных, логично держать рядом с токенами, а не дублировать по темам.

## Сценарии подключения CSS

### Подключить весь CSS пакета целиком

```ts
import '@feugene/granularity/styles.css'
```

Подходит, если приложение использует много компонентов и не хочет отдельно управлять CSS-сборкой.

### Перекрасить тему без granum

Своя палитра ложится **после** темы пакета под те же пары: токены компонентов
ядра (`--gr-button-*` и т.п.) приходят из `themes/slate.css` и ссылаются на роли,
поэтому достаточно переопределить роли.

```ts
import '@feugene/granularity/themes/slate.css'
import './styles/app-theme.css' // :root, [data-theme="slate-light"] { --gr-primary: … }
import '@feugene/granularity/styles/base.css'
```

В приложении на granum то же делают `modes.tokenOverrides` и `modes.define` записи темы в
`themes` (см. [`modes.md`](./modes.md)).

## Что важно помнить

- `styles.css` — foundation целиком: тема `slate` в обоих режимах + base. Utility-классов
  компонентов в нём нет.
- `src/styles/index.css` — source-группа, из которой он собирается.
- CSS компонента приезжает из манифеста через granum, а не с его чанком; отдельного subpath на него нет.
- если приложение уже собирает стили granum, прямой импорт `styles.css` обычно не нужен.

## RTL не поддерживается

Компоненты раскладываются физическими направлениями (`pl-`/`pr-`, `ml-`/`mr-`, `left-`/`right-`),
логических утилит (`ps-`/`pe-`, `ms-`/`me-`, `start-`/`end-`) в пакете почти нет, а атрибут `dir` не
читается нигде. В документе с `dir="rtl"` отступы, смещения и плавающие панели окажутся зеркальными:
пакет их не перевернёт.

Это решение, а не недоделка. Перевод на логические свойства меняет вид **каждого** компонента —
визуально ломающее изменение, которому место в мажоре, а не в патче. До тех пор поддержка
right-to-left остаётся за приложением.

## Темизация: канон

Режим включается **одним** способом — парой `<тема>-<режим>` в атрибуте
`data-theme` на `<html>` или на корне острова: `data-theme="slate-dark"`. Без
атрибута действует режим по умолчанию (`slate-light`). Классов `.light`/`.dark`
и прочих селекторов режима нет; вариант `dark:` движка строится по тем же
тёмным парам.

Рантайм-API переключения — `useTheme()` (реактивное состояние, persistence,
синхронизация между вкладками и с `prefers-color-scheme`) и `initThemeEarly()`
(ранний вызов до монтирования Vue, чтобы избежать «мигания»). Отдают они тему и
имя режима (`'dark'`), в атрибут пишут пару, а хранят ключ выбора: у основной темы —
имя режима, у дополнительной — `<тема>-<режим>` (подробно — [modes.md](./modes.md)).
Какие темы и режимы попадают в собранный CSS, решает `themes` конфига granum, а не
рантайм: они и их пары приходят в рантайм манифестом `virtual:granum/themes`.

```ts
import { initThemeEarly, useTheme } from '@feugene/granularity'
import manifest from 'virtual:granum/themes'

initThemeEarly({ manifest }) // до app.mount()

const { theme, mode, modes, isDark, setMode, toggleMode } = useTheme()
```

Выбор режима хранится в `localStorage` под ключом `gr-theme`.
