# Практики разработки приложений на стеке

Свод правил для **приложения**, а не для библиотеки. Каждое из них уже стоило
кому-то расследования и держится либо гейтом в пакете, либо явным контрактом в
документации — ссылка стоит рядом с правилом.

Соседние документы: [`getting-started.md`](./getting-started.md) — как поднять
приложение, [`installation.md`](./installation.md) — что поставить. Здесь — как
писать на этом дальше, чтобы не переделывать.

---

## 1. Импорт и граница пакета

**Компоненты — subpath-импортом.** `@feugene/granularity/components/GrButton`
попадает ровно в тот чанк, где нужен. Корневой барель удобен в прототипе, но на
нём гранулярность держится хуже — вся идея упаковки пакета в том, что вы платите
только за использованное ([`packaging.md`](./packaging.md)).

**Публичных точек входа ровно столько, сколько в `exports`.** Их 105:
компоненты, `./composables/*`, `./directives`, `./i18n`, `./theme`, `./tokens`,
`./testing`, `./vue`, `./granular-provider`. Внутрь `dist/` руками не ходить —
раскладка чанков меняется между версиями без предупреждения.

**Рядом с компонентом лежат три типа** — `GrXProps`, `GrXEmits`, `GrXInstance`
(гейт `src/__tests__/publicTypes.test.ts`). Пишете обёртку — берите их, а не
переобъявляйте:

```ts
import type { GrInputEmits, GrInputInstance, GrInputProps } from '@feugene/granularity/components/GrInput'

export interface MoneyInputProps extends GrInputProps {
  currency: string
}

export type MoneyInputEmits = GrInputEmits

export function focusFirst(control: GrInputInstance | undefined): void {
  control?.focus()
}
```

`GrXInstance` — это то, что компонент отдал через `defineExpose`; он и нужен для
`ref` с вызовом `focus()`.

## 2. Настраивать конфигом, а не копипастой пропов

`GrConfigProvider` задаёт дефолты на поддерево: размер, `componentDefaults`,
тему, базу `z-index`, точку монтирования оверлеев
([`components/GrConfigProvider.md`](./components/GrConfigProvider.md)).

Порядок разрешения — сверху вниз, точечное побеждает общее
([`sizes.md`](./sizes.md#как-разрешается-значение)):

1. локальный проп на компоненте;
2. `componentDefaults[Component]` ближайшего провайдера;
3. глобальный `size` того же провайдера;
4. дефолт компонента.

```vue
<GrConfigProvider size="sm" :component-defaults="{ GrButton: { size: 'lg' } }">
  <GrInput v-model="q" />                  <!-- sm  -->
  <GrButton>Найти</GrButton>               <!-- lg  -->
  <GrTextarea v-model="note" size="md" />  <!-- md  -->
</GrConfigProvider>
```

**Знать про два отклонения**, иначе будете искать, почему конфиг «не работает»:
`GrBadge` читает только `componentDefaults` (глобальный `size` до него не
доходит), `GrKbd` из четырёх ступеней различает две. Список ведётся в гейте
`componentSize.test.ts` и проверяется на протухание.

**`GrComponentDefaults` типизирован только тем, что вы импортировали.** Реестр
наполняется через declaration merging из папок компонентов, попавших в ваш граф
типов. Импортировали одну кнопку — в `componentDefaults` типизирована одна
кнопка, а пустой реестр примет любой литерал без ошибки. Не полагайтесь на
автодополнение как на проверку — стенд `apps/playground-config` держит именно
этот инвариант.

## 3. Формы

Самая большая прикладная поверхность, и большая часть граблей — здесь.

**Различать `update:modelValue` и `change`.** Первое — значение изменилось,
второе — пользователь его зафиксировал. Отправлять на сервер и писать в
аналитику по `change`.

**`clear` — отдельное событие не просто так.** По пустому значению вы не
отличите очистку от честного «пусто», а это разные вещи для валидации и метрик
([`form-controls.md`](./form-controls.md#события)).

**Снимок формы переснимать после загрузки данных.** `resetFields()` возвращает
модель к снимку, а снимок берётся **при монтировании**:

```ts
const data = await api.load()
Object.assign(model, data)
form.value?.setSnapshot()
```

Без этого «сброс» на форме редактирования вернёт пустой объект, каким модель
была до ответа сервера ([`components/GrForm.md`](./components/GrForm.md)).

**`isValid` — это «известных ошибок нет», а не «форма валидна».** До первого
`validate()` он означает «никто не проверял». Не показывать по нему зелёную
галочку.

**Выключать форму целиком через `disabled` у `GrForm`** — он уезжает в контекст
поля и дальше в контролы. Обходить контролы по одному на время отправки не
нужно.

**Ограничения на файлы задавать правилом формы**, а не пропами поля: правило
`file: { accept, maxSizeMb, … }` собирает те же валидаторы, что использует
`GrFileUpload` и `vDropzone`, поэтому текст ошибки и поведение не разъезжаются
([`file-validation.md`](./file-validation.md)).

**Обязательность приходит из двух мест** — правило `required` или проп
`required` у `GrFormField`. Оба участвуют и в звёздочке, и в валидации.

## 4. Обёртки над контролами

Шестнадцать контролов пакета соблюдают один контракт, и он существует ровно
затем, чтобы ваша обёртка над одним работала над любым.

**Пропы объявлять, а не оставлять на fallthrough.** Необъявленный проп протекает
на корень и в разметке выглядит реализованным; `ariaLabel` Vue вдобавок сама
нормализует в `aria-label`, и на глаз такая обёртка неотличима от настоящей.

**Объявили emit — разведите его.** Объявленный emit **уходит из `$attrs`**: пока
события нет в `defineEmits`, нативное протекает на корень и `@focus` работает
само собой. Объявить и не переизлучить — значит молча сломать `@focus` у всех,
кто его уже слушает.

**Не ждать `blur` при переходе внутри группы.** У `GrRadioGroup`, `GrSegmented`,
`GrCheckboxGroup`, диапазонного `GrSlider`, `GrInputTag` фокус ходит внутри, и
события эмитятся только на пересечении границы контрола. У комбобоксов частью
контрола считается и телепортированная панель.

**Слот — это роль.** Одна роль во всём пакете зовётся одним именем: `prefix` /
`suffix`, `header` / `footer`, `title` / `description` / `label`, `error`,
`empty` / `loading`, `actions`, `trigger` / `content`. Держитесь словаря в своих
компонентах — тогда переход с одного контрола на другой не переписывает шаблон.

**Колонка аддонов «плывёт» — это `*Fixed`.** Без него каждое поле меряет свой
аддон по факту, и соседние поля не совпадают по ширине.

## 5. Своё поверх страницы: оверлеи и слои

**Свой оверлей обязан уезжать в общий портал.** Слой вне ветки
`<div id="gr-portal">` будет помечен `inert` вместе со страницей, как только
откроется модалка:

```ts
import { usePortalTarget } from '@feugene/granularity'

const { target, enabled } = usePortalTarget()
// <teleport :to="target" :disabled="!enabled">…</teleport>
```

**Модальный слой руками не собирать** — брать `GrModal` (или `GrPopover` с
`modal`, если панель обязана остаться у триггера). Вместе со слоем достаются
общий стек Esc, `inert` для нижних окон, scroll-lock и ловушка фокуса.

**Немодальный собирается из трёх кусков**: `useFloating` (позиция и слой),
`useDismissible` (очередь Esc), `v-click-outside`. Ловушки фокуса здесь быть не
должно ([`overlays.md`](./overlays.md#собрать-свой-оверлей)).

**Свой `position: fixed` — только через токен**: `z-[var(--gr-z-modal)]`,
никаких литералов. Литералы допустимы для порядка внутри компонента, пока
значение меньше 50 ([`z-index.md`](./z-index.md)).

**У корня портала не должно быть ни стилей, ни классов.** `transform`, `filter`,
`contain`, `perspective`, `will-change` создают containing block для
`position: fixed`, и панели начнут считать позицию от портала, а не от вьюпорта.

**Свой контейнер вместо `body`** (микрофронтенд, shadow DOM, CSS-скоупинг) —
`portalTarget` у `GrConfigProvider` или `teleportTo` у компонента.

## 6. Доступность

**Новый виджет — паттерн из WAI-ARIA APG целиком**, включая клавиатуру. Половина
паттерна хуже отсутствия: скринридер объявит роль, которой поведение не
соответствует. Составной виджет — одна остановка Tab плюс roving tabindex;
`Home`/`End` забывают чаще всего ([`keyboard.md`](./keyboard.md#чек-лист-для-нового-виджета)).

**Фокус после закрытия не переставлять руками.** Возврат на триггер делает стек
слоёв; свои `nextTick`/`setTimeout` с ним конфликтуют.

**Состояние — в разметку, событие — в объявитель.** «Загружается», «ничего не
найдено», «осталось 12 символов» живут рядом с виджетом; «Тег удалён»,
«Изображение 2 из 5» — это `useAnnouncer()`, у них своего места в разметке нет
([`announcer.md`](./announcer.md)).

**Своё визуальное скрытие для живого региона не писать.** `display: none` и
`visibility: hidden` AT не читает, а класс `sr-only` на императивно созданном
узле UnoCSS не сгенерирует ни при каком safelist.

## 7. Темы

**`useTheme()` умеет ровно две темы** — он типизирован как `'light' | 'dark'`.
Нужна третья — заводите свой контроллер поверх `[data-theme]` и подключайте CSS
темы обычным импортом. Рабочий пример — `apps/playground-theme`.

**`themes.themeFiles` заменяет тему, а не добавляет.** Список тем — пересечение
`themes.names` с тем, что объявил провайдер; третью тему через пресет не
подключить ([`unocss.md`](./unocss.md)).

**Тему собирать из данных, а не писать CSS руками.** `extendTheme` (поверх
готовой) и `createTheme` (с нуля) из `@feugene/granularity/theme` отдают и
токены, и CSS; `createTheme` падает на неполноте, а `tone()` закрывает роли
пачками. Сгенерированный файл держите под скриптом с флагом `--check`, чтобы он
не разошёлся с источником ([`theming.md`](./theming.md)).

**Ставить тему до первого рендера** — инлайновым скриптом в `<head>`. Ключ
`gr-theme`, атрибут `[data-theme]` — тот же контракт, что у `useTheme()`. Иначе
пользователь с тёмной темой увидит вспышку светлой.

**Проверять контраст гейтом, а не глазами.** В пакете это делают
`GrLink.contrast.test.ts` и `tonePalette.test.ts`; в приложении с своей темой —
тот же приём (образец — `apps/playground-theme/src/__tests__/theme.test.ts`).

## 8. Локализация

Подробно — в [`getting-started.md`](./getting-started.md#локализация). Три вещи,
которые касаются именно прикладного кода:

**Свой блок для своих строк.** Реестр `fint-i18n` мержит источники одного блока
по ключам: словарь, севший на чужой блок, столкнётся с ним молча, на первом же
совпавшем верхнем ключе.

**В словарь не кладут то, что знает `Intl`**: названия месяцев и дней недели,
порядок частей даты, 12/24 часа, «вчера», форматы чисел. Строка в словаре на
такую тему означает, что интерфейс будет знать столько языков, сколько успели
вписать ([`localization.md`](./localization.md)).

**Форматирование брать там же, где переводы** — `useI18nFormat()` из
`@feugene/fint-i18n/vue`. Второй `Intl` в приложении однажды разойдётся с первым
в правилах.

## 9. Движение

**`motion-safe:` не писать** — он не сгенерируется. Обычные `transition-*` и
`animate-*` закрывает глобальный блок `prefers-reduced-motion`.

**Свой `@keyframes` проверить по двум признакам**: `animation-fill-mode:
forwards`/`both` и то, что показывает исходный кадр. Есть любой — нужен
собственный `@media (prefers-reduced-motion: reduce)` и решение, что показывать
вместо анимации.

**Движение из JS блок не покрывает.** `scrollIntoView({ behavior: 'smooth' })` и
ручные твины читают `matchMedia('(prefers-reduced-motion: reduce)')` сами — и
читают в момент старта, а не в теле `setup`: на сервере `matchMedia` нет, и
первый клиентский рендер разошёлся бы с серверным ([`motion.md`](./motion.md)).

**Анимация, несущая смысл** (прогресс, таймер, порядок шагов), под `reduce`
обязана либо сохранить смысл без движения, либо честно исчезнуть. Мгновенно
доигранная анимация, показывающая неверное состояние, хуже отсутствующей.

## 10. Данные и производительность

**`rowKey` у таблицы с выбором задавать явно.** Строка без значения по ключу
получает синтетический ключ, привязанный к идентичности объекта: он переживает
сортировку, но не переживает перезагрузку данных — и `v-model:selected` из
прошлого набора не совпадёт ни с чем ([`components/GrDataTable.md`](./components/GrDataTable.md)).

**Виртуализацию включать осознанно.** На сотне строк выигрыша нет, а разметка
меняется — вместе с ней меняется и то, что находит ваш `querySelector`.
Перетаскивание работает только по отрисованным строкам
([`virtual-list.md`](./virtual-list.md#ограничения)).

**Сужать `components` в пресете**, когда набор компонентов приложения устоялся:
в CSS попадёт только то, что используется. До этого момента дешевле оставить
поведение по умолчанию, чем ловить пропавшие стили.

## 11. SSR

Полный каркас — в [`getting-started.md`](./getting-started.md#каркас-ssr),
контракт компонентов — в [`ssr.md`](./ssr.md). Прикладные правила:

- **`<ClientOnly>` вокруг компонентов пакета не нужен ни одному** — он только
  убьёт серверную разметку. Обёртка нужна вашему коду, который читает среду
  прямо в шаблоне.
- **Императивные API прячут вызов, а не разметку**: `useDialogService().confirm()`
  и `createLoading()` монтируют хост в `document.body`.
- **DOM-идентификаторы — только `useId()`.** Ни `instance.uid` (на сервере
  счётчик растёт между запросами, на клиенте стартует с нуля), ни
  `Math.random()`. Расхождение придёт молча — через `id`, `aria-controls`,
  `aria-labelledby`.
- **Значение, зависящее от среды** (`navigator`, ширина окна, тема ОС), в первом
  рендере не использовать: `ref` с серверным значением плюс уточнение в
  `onMounted`.

## 12. Тесты приложения

Пакет отдаёт помощники — `@feugene/granularity/testing`. Раннер и способ
монтирования ваши: точка входа не зависит ни от `vitest`, ни от
`@vue/test-utils` ([`testing.md`](./testing.md)).

| Помощник                                                | Зачем                                            |
|---------------------------------------------------------|--------------------------------------------------|
| `granularityGlobal({ size, componentDefaults, i18n })`  | то же, что кладёт в `provide` `GrConfigProvider` |
| `press` / `move` / `release` / `drag` / `cancelPointer` | указательные жесты                               |
| `keydown` / `composingKeydown`                          | клавиатура и IME                                 |
| `mockRect` / `stackRects`                               | геометрия в jsdom                                |
| `announced()`                                           | текст живого региона                             |
| `resetGranularityDom`                                   | уборка между тестами                             |
| `stubMatchMedia({ reducedMotion })`                     | задать ответ `matchMedia`                        |

**`afterEach(resetGranularityDom)` — не гигиена, а условие работы.** Одного
`document.body.innerHTML = ''` мало: корень портала и хост живого региона
кэшированы модулями и после такой очистки указывают на узлы **вне документа**.
Следующий монтаж телепортирует оверлеи туда, тест их не находит — без единой
ошибки в консоли.

**Жест писать помощниками.** Движение и отпускание слушает `window`, а не
элемент: тест, отправивший `pointermove` в тот же элемент, не проверяет ничего и
делает это молча. Плюс `PointerEvent` в jsdom не реализован.

**`announced()` обязательно ждать** — `announce` пишет в регион отложенным
макротаском, и это условие работы: регион, в котором текст появился в том же
кадре, что и сам регион, часть скринридеров не объявляет вовсе.

**Клавиатуру в jsdom не проверить.** Там нет ни перемещения фокуса по `Tab`, ни
активации по `Enter`: `trigger('click')` проверяет обработчик, но не то, что до
него можно добраться. Клавиатурный контракт и всё, чему нужен layout, — в живой
браузер (образец — `apps/showcase/e2e/interaction.spec.ts`).

## 13. Чего пакет намеренно не делает

Чтобы не искать в нём то, чего там нет:

| Не делает                                             | Что вместо                                                 |
|-------------------------------------------------------|------------------------------------------------------------|
| Плюрализацию, форматы чисел, дат и валют              | `Intl` через ваш i18n-слой                                 |
| RTL                                                   | не поддерживается осознанно ([`styling.md`](./styling.md)) |
| Управление состоянием и роутинг                       | ваш стор и роутер                                          |
| Автопрокрутку при перетаскивании в виртуальном списке | пока нет                                                   |
| Потоковый SSR (`renderToWebStream`)                   | не покрыт стендом                                          |
