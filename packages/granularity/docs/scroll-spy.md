# `useScrollSpy` — где сейчас читают

Композабл владеет всем, что следует из **положения прокрутки**: линией активации,
выбором активного раздела, прокруткой к нему и закрепом подсветки на время этой
прокрутки. Всё, что следует из того, что пункт оглавления является **ссылкой** —
разметка, `aria-current`, модификаторы клика, перенос фокуса, — остаётся у
компонента.

В пакете на нём работает [`GrScrollSpy`](./components/GrScrollSpy.md). Берите
композабл, если оглавление у вас своё: разметка нестандартная, пункты приезжают из
роутера, подсветка нужна не в списке, а в прогресс-полосе.

```ts
import { useScrollSpy } from '@feugene/granularity'

const spy = useScrollSpy({
  sections: () => sections.value.map(section => section.id),
  offset: () => 112,
})
```

```vue
<a
  v-for="section in sections"
  :key="section.id"
  :href="`#${section.id}`"
  :aria-current="spy.active.value === section.id ? 'location' : undefined"
  @click.prevent="spy.scrollTo(section.id)"
>
  {{ section.label }}
</a>
```

## Активным считается раздел, чей заголовок прошли последним

Не «самый видимый». Максимум доли пересечения ошибается двумя способами: длинный
раздел выигрывает у короткого независимо от того, что читают, и подсветка
отскакивает назад, когда следующий раздел только показался снизу.

Порядок массива на ответ не влияет — выбор идёт по геометрии. Отдельным правилом
закрыт последний раздел: короче остатка экрана он верхом до линии не доезжает
никогда, потому что прокрутка кончается раньше, поэтому на дне активным становится
он.

## Наблюдателя мало

`IntersectionObserver` отвечает на «пересекли ли линию» и не вызывается, когда
прокрутка доезжает до конца: за последние пиксели ни один край ничего не
пересекает. Поэтому композабл держит ещё и `scroll`-слушатель, читающий одно
число — доехали ли до дна. Он же отпускает закреп.

## Отступ приходит числом

`offset` — **пиксели**, а не CSS-длина. Резолв `4rem` или `var(...)` требует
`getComputedStyle`, то есть DOM, а композабл обязан оставаться проверяемым без
него. Компонент резолвит длину сам и отдаёт число; свой потребитель делает так же.

## Закреп на время прокрутки

`scrollTo` сразу ставит активным выбранный раздел и запирает обновления, пока
прокрутка не уляжется, — иначе подсветка добежала бы по промежуточным разделам.
Закреп снимается, как только пользователь тронул прокрутку: колесом, пальцем,
клавишей или полосой прокрутки.

`pin(id)` даёт тот же закреп снаружи — когда страницу прокручивает не оглавление:
восстановление позиции по адресу, переход к первому полю с ошибкой.

## API

| | |
| --- | --- |
| `sections` | геттер идентификаторов разделов |
| `elementFor` | элемент по идентификатору; по умолчанию `document.getElementById` |
| `scroller` | скроллпорт; не задан — ищется от первого раздела, не найден — документ |
| `offset` | отступ линии активации в пикселях |
| `disabled` | наблюдение выключено, `active` сбрасывается |
| `onChange` | активный сменился |
| → `active` | активный раздел или `null` |
| → `scrollTo` | прокрутить и закрепить |
| → `refresh` | перечитать отступ, скроллпорт и геометрию |
| → `pin` | закрепить или отпустить вручную |

## Чего композабл не делает

- **не собирает оглавление по заголовкам** — список разделов передаёте вы;
- **не рендерит ничего** — ни разметки, ни `aria-current`;
- **не угадывает без наблюдателя.** Там, где `IntersectionObserver` отсутствует,
  `active` остаётся `null`: один замер на монтировании был бы верен ровно до
  первой прокрутки, а `aria-current` на неактивном пункте — ложь диктору.
  Прокрутка по клику при этом продолжает работать.

## Серверный рендер

В теле композабла нет ни одного обращения к DOM: наблюдатель, замеры и слушатели
живут в `onMounted`, `matchMedia` спрашивается в момент клика. `active` на сервере
и на первом клиентском кадре — `null`, поэтому разметка совпадает и гидрация не
расходится.
