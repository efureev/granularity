# `useAnnouncer` — объявить событие скринридеру

Общий живой регион (`aria-live`) пакета. Нужен, когда произошло что-то, о чём незрячему пользователю надо сказать, а
показать это негде: «Ссылка скопирована», «Строка удалена», «Найдено 12 записей».

```ts
import {useAnnouncer} from '@feugene/granularity'

const {announce} = useAnnouncer()

announce('Ссылка скопирована')
announce('Не удалось сохранить', {politeness: 'assertive'})
```

Композабл не требует setup-контекста — его можно звать из стора, обработчика, перехватчика запросов. `useAnnouncer()` в
`setup` просто ставит регион пораньше.

## Когда объявитель, а когда свой регион

Граница проходит по природе текста, а не по удобству.

|              | Своё в разметке                                                                   | Объявитель                                                          |
|--------------|-----------------------------------------------------------------------------------|---------------------------------------------------------------------|
| Что за текст | **состояние** виджета: «загружается», «ничего не найдено», «осталось 12 символов» | **событие**: произошло и прошло                                     |
| Где живёт    | внутри виджета, рядом с содержимым, к которому относится                          | нигде: своего места в разметке у него нет                           |
| Пример       | счётчик `GrInput`, состояние `GrDataTable`, номер страницы `GrPagination`         | «Тег удалён» у `GrInputTag`, «Изображение 2 из 5» у `GrImageViewer` |

Состояние, вынесенное в объявитель, теряет связь с виджетом; событие, прибитое к разметке, требует узла, который
существует только ради текста.

## API

```ts
function useAnnouncer(): GrAnnouncer

interface GrAnnouncer {
    announce: (message: string, options?: GrAnnounceOptions) => void
    clear: (politeness?: GrAnnouncerPoliteness) => void
}

interface GrAnnounceOptions {
    politeness?: 'polite' | 'assertive'  // по умолчанию 'polite'
    clearAfterMs?: number                // по умолчанию 7000; 0 — не стирать
}
```

**`polite` или `assertive`.** `assertive` прерывает текущую речь и уместен только там, где пропустить нельзя: отказ
операции, потеря соединения. Всё остальное — `polite`, диктор дочитает начатое. Ассертивный поток объявлений превращает
страницу в неработающую: пользователь не успевает дослушать ни одно.

**`clearAfterMs`.** Регион остаётся в DOM, и пользователь виртуального курсора наткнётся на его текст при обходе
страницы — через минуту после события это уже дезинформация. Ставить `0` стоит только для текста, который остаётся
правдой.

## Устройство

```html

<div id="gr-announcer" data-gr-live-region>
    <div role="status" aria-live="polite" aria-atomic="true">…</div>
    <div role="alert" aria-live="assertive" aria-atomic="true">…</div>
</div>
```

Хост создаётся при первом `useAnnouncer()` и живёт в корне портала. Три решения в нём неочевидны, и каждое отвечает на
конкретный отказ.

**Регион один на документ, а не на приложение.** У `useToast` и
`useDialogService` состояние app-scoped через плагин — там это защищает от утечки между SSR-запросами и от общей очереди
у двух приложений на странице. Живой регион не состояние, а сток в единственный канал AT документа: два приложения с
двумя регионами не изолируются, а рискуют объявить одно и то же дважды. Плагина у объявителя поэтому нет.

**Узлы появляются раньше текста.** Регион, который возникает в DOM сразу с содержимым, часть AT не объявляет вовсе.
Поэтому `useAnnouncer()` ставит оба узла пустыми, а `announce()` пишет текст следующим тиком. По той же причине перед
каждой записью регион очищается: без пустой фазы повтор того же сообщения не даёт мутации и остаётся неозвученным.

**Хост не гасится `inert`.** Стек слоёв при открытии модалки помечает `inert`
всё, кроме ветки оверлея, а `inert` выбрасывает поддерево из дерева доступности. Хост объявителя помечен
`data-gr-live-region` и попадает в список пропуска рядом с корнями оверлеев — иначе объявитель молчал бы ровно под
открытым диалогом, там, где «сохранено» и «ошибка сети» и нужны.

## SSR

`announce()` на сервере — no-op: живой регион это узел документа, а документа там нет. Ничего оборачивать в `ClientOnly`
не нужно и гейта на плагин, как у
`useToast`, здесь нет — переносить между запросами объявителю нечего.

## Своё скрытие не писать

Узлы скрыты инлайновым стилем, а не классом `sr-only`. Класс здесь не сработал бы в принципе: узел создаётся
императивно, в `dist/components/**` его нет, и UnoCSS правило для него не сгенерирует ни при каком safelist. По той же
причине не подходят `display: none` и `visibility: hidden` — их содержимое AT не читает.
