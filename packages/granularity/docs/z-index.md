# Слоирование: z-index и стек оверлеев

Документ описывает **фактическое** состояние слоёв в пакете: шкалу, её пользователей, отклонения и правила для новых
компонентов.

## Шкала

Единственный источник истины — токены в `styles/tokens.css` (генерируются из
`tokens/foundation.json`, группа `Layering: z-index scale`):

| Токен             | Значение | Слой                                                                 |
|-------------------|----------|----------------------------------------------------------------------|
| `--gr-z-dropdown` | `1000`   | якорные floating-панели: dropdown, select, tree-select, autocomplete |
| `--gr-z-tooltip`  | `1050`   | тултипы                                                              |
| `--gr-z-modal`    | `1100`   | модальные окна и диалоги                                             |
| `--gr-z-loading`  | `1150`   | полноэкранный оверлей загрузки                                       |
| `--gr-z-toast`    | `1200`   | тосты                                                                |

Шаг между слоями — 50: он оставляет место приложению вклиниться между уровнями (например, свой sticky-хедер под
дропдауном), не переопределяя токены пакета.

### Почему floating-панели НИЖЕ модалок

Контринтуитивно, но правильно: поповер, открытый **внутри** модалки, не теряется под ней, потому что он лежит внутри её
stacking-контекста. А поповер, открытый **снаружи** модалки, перекрывать её не должен — и не перекрывает.

За пределы своего поддерева floating-компоненты не выходят по построению:
панель телепортируется в `body`, но открыта только пока жив триггер, а клик вне её закрывает (`v-click-outside`).

### Почему загрузка выше модалок

Полноэкранная загрузка — это блокировка приложения целиком, а не части UI: пока она идёт, пользователь не должен
дотянуться ни до чего, включая открытое окно. Инлайновая загрузка (оверлей на своём контейнере) к шкале отношения не
имеет и живёт на `z-10` внутри собственного stacking-контекста.

### Почему тосты выше всего

Тост — уведомление уровня приложения, а не части UI. Он обязан быть виден поверх открытой модалки, иначе сообщение об
ошибке фонового запроса пропадёт.

## Кто какой слой использует

| Компонент                                                                                                              | Слой              | Как задан                                                 |
|------------------------------------------------------------------------------------------------------------------------|-------------------|-----------------------------------------------------------|
| `GrDropdown`, `GrSelect`, `GrAutocomplete`, `GrTreeSelect`                                                             | `--gr-z-dropdown` | `useFloating({ zIndexVar })`                              |
| `GrTooltip`                                                                                                            | `--gr-z-tooltip`  | `useFloating({ zIndexVar: '--gr-z-tooltip' })`            |
| `GrModal` (и всё, что на нём: `GrDialog`, `GrConfirmDialog`, `GrPromptDialog`, `GrCommandPalette`, `useDialogService`) | `--gr-z-modal`    | `grModalStyles.ts`: `fixed inset-0 z-[var(--gr-z-modal)]` |
| `GrDrawer`                                                                                                             | `--gr-z-modal`    | `grDrawerStyles.ts`: `fixed inset-0 z-[var(--gr-z-modal)]` |
| `GrImageViewer`                                                                                                        | `--gr-z-modal`    | инлайн-стиль `z-index: var(--gr-z-modal)`; проп `zIndex` — escape-hatch |
| `GrLoading` (fullscreen), директива `v-loading`                                                                        | `--gr-z-loading`  | `grLoadingStyles.ts`: `fixed inset-0 z-[var(--gr-z-loading)]`; проп/опция `zIndexVar` — escape-hatch |
| `GrToaster`                                                                                                            | `--gr-z-toast`    | класс `z-[var(--gr-z-toast)]` на контейнере               |

`useFloating` принимает `zIndexVar` и подставляет `z-index: var(<token>)` в инлайн-стиль плавающего элемента. Дефолт —
`--gr-z-dropdown`, поэтому новый якорный компонент попадает в правильный слой без настройки.

## Отклонения (актуально на 2026-08-06)

Отклонений нет: все компоненты, кладущие `position: fixed` поверх страницы, сидят на шкале.

Локальные значения ниже 50 к шкале отношения не имеют: это порядок внутри собственного stacking-контекста компонента —
`z-[1]` у активного сегмента
`GrSegmented` и `GrButtonGroup`, sticky-шапка `GrTable`, `z-0`/`z-10` у бэкдропа и панели `GrModal`, `z-10` у контента
`GrImageViewer`. Их трогать не нужно.

Отклонения зафиксированы тестом `src/__tests__/layering.test.ts`: список закрытый, новый компонент с собственным числом
в диапазоне страничных оверлеев (≥ 50) уронит сборку. Если отклонение починили — удалите запись из теста и из таблицы
выше.

## Правила для нового компонента

1. **Якорная панель** (что-то, что позиционируется относительно триггера) —
   `useFloating`, слой не указывать: дефолт уже `--gr-z-dropdown`.
2. **Модальный слой** — строить на `GrModal`, а не на своём `fixed`: вместе со слоем достаются общий стек слоёв
   (порядок Esc и `inert` для нижних окон), scroll-lock и фокус-ловушка.
3. **Свой `position: fixed` поверх страницы** — только через токен (`z-[var(--gr-z-modal)]`), никаких литералов. Нужен
   новый слой — заводить токен в `tokens/foundation.json`, а не число в компоненте.
4. **Порядок внутри компонента** (`z-0`, `z-[1]`, `z-10`) — литералы допустимы, пока значение меньше 50: это не
   глобальный слой. Гейт ловит именно диапазон страничных оверлеев.

## Стек оверлеев: не только z-index

Порядок отрисовки — половина задачи. Вторая половина — кто получает Esc и фокус, когда открыто несколько окон **из
разных деревьев рендера** (обычная ситуация:
`useDialogService` монтирует диалог отдельным `render()` в `body`).

Готовые библиотеки диалогов держат собственный стек на каждое дерево рендера,
поэтому каждое окно считает себя верхним. Пакет решает это **одним** стеком слоёв: в нём и модалки, и `GrDrawer`, и `GrImageViewer`, и панели
`GrSelect` / `GrAutocomplete` /
`GrTreeSelect`, и меню `GrDropdown`, и подсказки `GrTooltip`. Порядок регистрации совпадает с порядком открытия, поэтому
«внутреннее» всегда выше «внешнего».

Список один, но вершины из него выводятся **две разные** — в этом вся суть:

| Что                | Кому достаётся                                 | Почему так                                                                                                   |
|--------------------|------------------------------------------------|--------------------------------------------------------------------------------------------------------------|
| **Esc**            | последнему слою любого рода                    | пользователь видит верхним именно его: дропдаун внутри модалки закрывает себя, следующий Esc — модалку       |
| **`inert`**        | модальным слоям ниже последнего **модального** | немодальный поповер модалку не понижает, иначе окно ушло бы в `inert` вместе со своим же открытым дропдауном |
| **возврат фокуса** | слою, который закрылся                         | и только если на момент закрытия фокус всё ещё внутри него (см. ниже)                                        |

Esc обрабатывается единым capture-обработчиком на `window`: он срабатывает раньше локальных обработчиков, гасит событие
(`stopImmediatePropagation`) и закрывает только верхний слой. Если верхний открыт с `closeOnEsc: false`, событие всё
равно не проваливается вниз — иначе Esc закрыл бы то, что пользователь не видит верхним.

Вести эти вершины в двух независимых реестрах нельзя: реестры описывают один и тот же порядок и расходятся молча —
достаточно оверлея, который зарегистрировался в одном и забыл про другой.

Практическое следствие: **вложенные диалоги работают** (например, `prompt`
поверх `confirm`) — фокус в поле верхнего не «воруется» нижним окном, а Esc закрывает именно верхнее.

**Фокус-ловушку стек не делает** — это отдельный примитив `useFocusTrap`, и связка «слой + ловушка» собирается в
компоненте: поповеру ловушка вредна, Tab обязан уводить фокус наружу и закрывать его.

Стек ловушку **питает**: `root` каждого слоя доступен через `rootsAbove()`, и модальное окно отдаёт эти корни ловушке
как дополнительные контейнеры. Без этого панель `GrSelect`, открытая внутри модалки, теряла бы фокус: в DOM она
телепортирована в `body`, то есть лежит вне поддерева окна.

**Возврат фокуса** — по одному правилу: восстанавливаем элемент, активный до открытия, только если на момент закрытия
фокус всё ещё внутри слоя. Ушёл пользователь сам (кликнул в другое поле) — фокус уже там, отбирать нельзя. Эвристика
«возвращать, если открыли с клавиатуры» промахивается в обе стороны.

Публичный вход — композабл `useOverlayLayer()`:

```ts
import {useOverlayLayer} from '@feugene/granularity'

const open = ref(false)
const panel = ref<HTMLElement | null>(null)

useOverlayLayer(open, () => {
    open.value = false
}, {root: panel})
```

| Опция             | Смысл                                                                               |
|-------------------|-------------------------------------------------------------------------------------|
| `modal`           | слой модального класса: понижает модалки под собой в `inert` (по умолчанию `false`) |
| `closeOnEscape`   | геттер: закрывать ли по Esc; `false` не пропускает событие ниже                     |
| `onTopmostChange` | «этот модальный слой сейчас верхний» — по нему компонент вешает `inert`             |
| `restoreFocus`    | вернуть фокус при закрытии (по умолчанию `true`)                                    |
| `root`            | корень слоя: правило возврата фокуса и `rootsAbove()` для ловушки нижнего слоя      |

`useDismissible(open, close)` остаётся как узкий фасад для немодальных слоёв:
это `useOverlayLayer` с `modal: false` и без возврата фокуса.

Свой поповер или меню, построенные на `useFloating()`, обязаны регистрироваться в том же стеке — иначе они снова
разъедутся с оверлеями библиотеки по Esc. Закрытие по клику вне слоя живёт отдельно, в директиве `vClickOutside`: у Esc
есть порядок слоёв, у клика — точка попадания.

### Ловушка фокуса

```ts
import {useFocusTrap, useOverlayLayer} from '@feugene/granularity'

const layer = useOverlayLayer(open, close, {modal: true, root: panel})

useFocusTrap(panel, {
    active: () => open.value && isTopmost.value,
    containers: layer.rootsAbove,
})
```

| Опция           | Смысл                                                                                         |
|-----------------|------------------------------------------------------------------------------------------------|
| `active`        | геттер: ловушка держит фокус, только пока слой открыт и верхний                                 |
| `initialFocus`  | дефолтный приёмник фокуса; фокус, уже стоящий внутри слоя, он не перебивает                     |
| `fallbackFocus` | куда девать фокус, когда внутри нечего фокусировать (обычно панель с `tabindex="-1"`)          |
| `containers`    | дополнительные корни того же слоя — телепортированные панели, открытые изнутри                 |
| `restoreFocus`  | вернуть фокус при деактивации; у оверлеев пакета выключено — возврат делает стек по своему правилу |

Ловушка живёт на `keydown` и `focusin` документа, **без sentinel-узлов**: подход с двумя focus-guard кнопками по краям
кладёт в разметку интерактивные элементы, а внутрь контейнера с ARIA-ролью их класть нельзя (axe: `nested-interactive`).

Гейты — `src/__tests__/overlayLayer.test.ts` и `src/composables/__tests__/useFocusTrap.test.ts`.
