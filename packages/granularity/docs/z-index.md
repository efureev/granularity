# Слоирование: шкала z-index

Документ описывает **фактическое** состояние слоёв в пакете: шкалу, её пользователей, отклонения и правила для новых
компонентов.

Порядок отрисовки — только половина задачи. Кто получает Esc и фокус, что уходит
в `inert` и куда монтируются панели — [`overlays.md`](./overlays.md).

## Шкала

Единственный источник истины — токены в `styles/tokens.css` (генерируются из
`tokens/foundation.json`, группа `Layering: z-index scale`):

| Токен                | Значение | Слой                                                                 |
|----------------------|----------|----------------------------------------------------------------------|
| `--gr-z-bottom-nav`  | `850`    | нижняя навигация приложения (`GrBottomNav`)                          |
| `--gr-z-navbar`      | `900`    | прилипшая шапка приложения (`GrNavbar sticky`)                       |
| `--gr-z-dropdown`    | `1000`   | якорные floating-панели: dropdown, select, tree-select, autocomplete |
| `--gr-z-tooltip`     | `1050`   | тултипы                                                              |
| `--gr-z-modal`       | `1100`   | модальные окна и диалоги                                             |
| `--gr-z-loading`     | `1150`   | полноэкранный оверлей загрузки                                       |
| `--gr-z-toast`       | `1200`   | тосты                                                                |

Шаг между слоями — 50: он оставляет место приложению вклиниться между уровнями (например, свой sticky-хедер под
дропдауном), не переопределяя токены пакета.

### Почему floating-панели НИЖЕ модалок

Контринтуитивно, но правильно: поповер, открытый **внутри** модалки, не теряется под ней, потому что он лежит внутри её
stacking-контекста. А поповер, открытый **снаружи** модалки, перекрывать её не должен — и не перекрывает.

За пределы своего поддерева floating-компоненты не выходят по построению:
панель телепортируется в `body`, но открыта только пока жив триггер, а клик вне её закрывает (`v-click-outside`).

### Почему загрузка выше модалок

Полноэкранная загрузка — это блокировка приложения целиком, а не части UI: пока она идёт, пользователь не должен
дотянуться ни до чего, включая открытое окно. Инлайновая загрузка (оверлей на своём контейнере) к шкале отношения не
имеет и живёт на `z-10` внутри собственного stacking-контекста.

### Почему тосты выше всего

Тост — уведомление уровня приложения, а не части UI. Он обязан быть виден поверх открытой модалки, иначе сообщение об
ошибке фонового запроса пропадёт.

## Кто какой слой использует

| Компонент                                                                                                              | Слой              | Как задан                                                 |
|------------------------------------------------------------------------------------------------------------------------|-------------------|-----------------------------------------------------------|
| `GrBottomNav` c `position="fixed"`                                                                                     | `--gr-z-bottom-nav` | `grBottomNavStyles.ts`: `fixed bottom-0 … z-[var(--gr-z-bottom-nav)]` |
| `GrNavbar` c `sticky`                                                                                                  | `--gr-z-navbar`   | `grNavbarStyles.ts`: `sticky top-0 z-[var(--gr-z-navbar)]` |
| `GrDropdown`, `GrSelect`, `GrAutocomplete`, `GrTreeSelect`                                                             | `--gr-z-dropdown`    | `useFloating({ zIndexVar })`                              |
| `GrTooltip`                                                                                                            | `--gr-z-tooltip`  | `useFloating({ zIndexVar: '--gr-z-tooltip' })`            |
| `GrModal` (и всё, что на нём: `GrDialog`, `GrConfirmDialog`, `GrPromptDialog`, `GrCommandPalette`, `useDialogService`) | `--gr-z-modal`    | `grModalStyles.ts`: `fixed inset-0 z-[var(--gr-z-modal)]` |
| `GrDrawer`                                                                                                             | `--gr-z-modal`    | `grDrawerStyles.ts`: `fixed inset-0 z-[var(--gr-z-modal)]` |
| `GrImageViewer`                                                                                                        | `--gr-z-modal`    | инлайн-стиль `z-index: var(--gr-z-modal)`; проп `zIndexVar` — escape-hatch |
| `GrLoading` (fullscreen), директива `v-loading`                                                                        | `--gr-z-loading`  | `grLoadingStyles.ts`: `fixed inset-0 z-[var(--gr-z-loading)]`; проп/опция `zIndexVar` — escape-hatch |
| `GrToaster`                                                                                                            | `--gr-z-toast`    | класс `z-[var(--gr-z-toast)]` на контейнере               |

`useFloating` принимает `zIndexVar` и подставляет `z-index: var(<token>)` в инлайн-стиль плавающего элемента. Дефолт —
`--gr-z-dropdown`, поэтому новый якорный компонент попадает в правильный слой без настройки.

## Отклонения (актуально на 2026-08-06)

Отклонений нет: все компоненты, кладущие `position: fixed` поверх страницы, сидят на шкале.

Локальные значения ниже 50 к шкале отношения не имеют: это порядок внутри собственного stacking-контекста компонента —
`z-[1]` у активного сегмента
`GrSegmented` и `GrButtonGroup`, sticky-шапка `GrTable`, `z-0`/`z-10` у бэкдропа и панели `GrModal`, `z-10` у контента
`GrImageViewer`. Их трогать не нужно.

Отклонения зафиксированы тестом `src/__tests__/layering.test.ts`: список закрытый, новый компонент с собственным числом
в диапазоне страничных оверлеев (≥ 50) уронит сборку. Если отклонение починили — удалите запись из теста и из таблицы
выше.

## Правила для нового компонента

1. **Якорная панель** (что-то, что позиционируется относительно триггера) —
   `useFloating`, слой не указывать: дефолт уже `--gr-z-dropdown`.
2. **Модальный слой** — строить на `GrModal`, а не на своём `fixed`: вместе со слоем достаются общий стек слоёв
   (порядок Esc и `inert` для нижних окон), scroll-lock и фокус-ловушка.
3. **Свой `position: fixed` поверх страницы** — только через токен (`z-[var(--gr-z-modal)]`), никаких литералов. Нужен
   новый слой — заводить токен в `tokens/foundation.json`, а не число в компоненте.
4. **Порядок внутри компонента** (`z-0`, `z-[1]`, `z-10`) — литералы допустимы, пока значение меньше 50: это не
   глобальный слой. Гейт ловит именно диапазон страничных оверлеев.
