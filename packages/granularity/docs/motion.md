# Движение и `prefers-reduced-motion`

Документ описывает **фактический** контракт движения в пакете: чем он выражен,
почему именно так, что происходит с каждым видом анимации и что делать в новом
компоненте.

## Контракт

Пакет уважает системную настройку «уменьшить движение» целиком, а не по
компонентам. Носитель контракта — один блок в `src/styles/base.css`
(и его копия в `preflight.css`):

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-delay: 0ms !important;
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-delay: 0ms !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

Он покрывает **всё сразу**: 78 утилит `transition-*`, 7 `animate-spin`,
`<transition>`-обёртки шести оверлеев, покомпонентные `@keyframes` и код,
которого ещё нет.

## Длительности и кривые — токенами

Само движение задаётся токенами, а не числами в разметке:

| Токен | Значение | Где |
| --- | --- | --- |
| `--gr-duration-fast` | 150ms | смена состояния: цвет, рамка, фокус-кольцо, появление поповера |
| `--gr-duration-base` | 200ms | появление и уход слоя: модалка, drawer, тост, раскрытие |
| `--gr-duration-slow` | 300ms | длинные переходы; в компонентах пакета пока не используется |
| `--gr-ease-out` | `cubic-bezier(0.16, 1, 0.3, 1)` | появление: быстрый старт, мягкая остановка |
| `--gr-ease-in` | `cubic-bezier(0.7, 0, 0.84, 0)` | уход |

В разметке это arbitrary-утилиты `duration-[var(--gr-duration-fast)]` и
`ease-[var(--gr-ease-out)]`. Утилиты `duration-150` и `ease-out` не годятся:
первая зашивает число мимо темы, вторая берёт кривую из `presetMini`
(`cubic-bezier(0, 0, 0.2, 1)`), то есть движение задавал бы пресет, а не
дизайн-система. Гейт — `src/__tests__/styleTokens.test.ts`; он же запрещает
литералы вида `120ms` в собственном CSS компонента.

Токены — единственный канал настройки: приложение, которому нужна другая
динамика, меняет три значения, а не пересобирает классы.

## Почему глобальный блок, а не `motion-safe:`

Потому что `motion-safe:` в этой сборке **не работает**. Вариант
`motion-safe:` / `motion-reduce:` под `presetMini` не генерирует CSS вовсе:

```
animate-spin              → .animate-spin{animation:granularity-spin 1s linear infinite;}
motion-safe:animate-spin  → (пусто)
motion-reduce:transition-none → (пусто)
```

Расставленный по 85 местам, он дал бы ровно тот тихий баг, которым славится
safelist: класс в разметке есть, CSS нет, анимация продолжает играть. Проверять
это глазами невозможно — отличается только поведение при включённой системной
настройке.

Тот же довод против «`motion-safe:` на всякий случай»: даже если вариант
завезут, библиотека отдаёт **классы**, а CSS собирает приложение своим конфигом.
Контракт доступности не может зависеть от того, подключил ли потребитель нужный
вариант.

## Почему `0.01ms`, а не `none`

Гашение до `animation: none` / `transition: none` не даёт состояться событиям
`animationend` и `transitionend`. Слушатель на стороне потребителя (или будущий
наш) никогда бы их не дождался и оставил интерфейс в промежуточном состоянии.
`0.01ms` — это «мгновенно» для глаза и «состоялось» для событийной модели.

Задержки обнуляются вместе с длительностями: `transition-delay: 2s` вернул бы
ожидание, ради устранения которого блок и написан.

`!important` обязателен: у селектора `*` нулевая специфичность, без него он
проиграет любой утилите и любому инлайновому стилю (у полосы прогресса
`GrToaster` длительность приходит именно инлайном).

## Что происходит с каждым видом анимации

| Что | Под `reduce` |
| --- | --- |
| `transition-*` (78 мест) | длительность `0.01ms` — состояние меняется мгновенно |
| `<transition>` у оверлеев (6 компонентов) | появление/скрытие без фейда |
| `animate-spin` (7 мест) и `GrLoading` | вращение прекращается, иконка встаёт в `0deg` |
| `GrSkeleton` | `animation: none` — пульсация выключена |
| `GrToaster`, полоса прогресса | **скрыта** (см. ниже) |

Про спиннеры важно понимать, что они **не замирают под случайным углом**.
У `gr-loading-spin` и `granularity-spin` нет `animation-fill-mode`, поэтому,
отработав за `0.01ms`, элемент возвращается в исходное состояние: `transform:
none`, то есть аккуратная статичная иконка в правильной ориентации (проверено в
браузере с эмуляцией `reduce`).

Пульсацию взамен вращения пакет намеренно **не** включает: любая бесконечная
анимация — это движение, которого пользователь попросил не показывать. Состояние
загрузки остаётся объявленным текстом и ARIA, а не анимацией.

## Единственное исключение: полоса прогресса `GrToaster`

У неё `animation-fill-mode: forwards`. Сжатая клампом до `0.01ms`, она не
вернулась бы в исходное состояние, а зафиксировалась бы на конечном кадре
`scaleX(0)` — таймер выглядел бы истёкшим, пока тост ещё висит на экране.
Статичной её оставить тоже нельзя: полоса — единственный носитель этого смысла.
Поэтому под `reduce` она скрывается. Автозакрытие ведёт JS-таймер и не страдает,
а сам элемент и так `aria-hidden`.

Отсюда общее правило: **`fill-mode: forwards` (или `both`) — признак того, что
глобального клампа мало** и компоненту нужен собственный блок.

## Правило для нового компонента

1. Обычные `transition-*` и `animate-*` дополнительной работы не требуют —
   их закрывает глобальный блок. `motion-safe:` не писать: он не сгенерируется.
2. Свой `@keyframes` — проверить `animation-fill-mode`. Нет `forwards`/`both` →
   ничего делать не нужно, компонент вносится в `CLAMP_SAFE_KEYFRAMES` гейта.
   Есть → добавить в компонент собственный
   `@media (prefers-reduced-motion: reduce)` и решить, что показывать вместо
   анимации.
3. Анимация, которая **несёт смысл** (прогресс, таймер, порядок шагов), под
   `reduce` обязана либо сохранить смысл без движения, либо честно исчезнуть.
   Мгновенно доигранная анимация, показывающая неверное состояние, хуже
   отсутствующей.
4. Движение из JS (`scrollIntoView({ behavior: 'smooth' })`, ручные твины) блок
   не покрывает — такие места читают `matchMedia('(prefers-reduced-motion:
   reduce)')` сами. Сейчас в пакете таких мест нет.

Гейт — `src/__tests__/reducedMotion.test.ts`. Он проверяет наличие и состав
блока, **синхронность `base.css` и `preflight.css`** (до него она держалась
только на комментарии) и то, что каждый компонентный `@keyframes` либо обработан,
либо честно записан как безопасный под клампом.

## Ограничение

Блок живёт в глобальном слое. Потребитель, который сознательно подключает
`tokens.css` + тему **без** `base.css`/`preflight.css` (такой сценарий
документирован в [`styling.md`](./styling.md)), остаётся без него — и обязан
добавить эквивалент сам. При штатной интеграции через
`presetGranularNode` блок приезжает автоматически: granular-provider встраивает
`base.css` как preflight.
