# `useTree` — модель дерева без разметки

Композабл владеет всем, что можно посчитать про дерево, не рисуя его: раскрытием,
отметками с наследованием, фильтром, ленивой подгрузкой, перемещением узлов и —
главное — **плоским списком видимых строк** с уровнем, позицией среди соседей и
размером набора.

На нём работает [`GrTree`](./components/GrTree.md). Берите композабл, когда должна
отличаться сама разметка или роли: дерево, у которого верхний уровень — заголовок
раздела, а не `treeitem`; прогресс-полоса вместо списка; узлы, разложенные по
колонкам. Если отличается только вид — это `GrTree` с другими токенами, см.
раздел «Готовые виды» на его странице.

```ts
import { useTree } from '@feugene/granularity'

const tree = useTree({
  adapter,
  data: () => nodes.value,
  defaultExpandedKeys: () => ['root'],
})
```

```vue
<div
  v-for="row in tree.visibleRows.value"
  :key="row.node.key"
  role="treeitem"
  :aria-level="row.node.level"
  :aria-posinset="row.posInSet"
  :aria-setsize="row.setSize"
  :aria-expanded="row.isLeaf ? undefined : row.isExpanded"
  :style="{ paddingInlineStart: `${(row.node.level - 1) * 20}px` }"
  @click="tree.toggleExpand(row.node)"
>
  {{ row.node.label }}
</div>
```

## Плоский список — не оптимизация, а условие

Рекурсивный рендер стоит по инстансу компонента на каждый раскрытый узел: дерево
на 2 000 видимых строк превращается в 2 000 компонентов со своими вычислениями и
подписками. Поэтому модель отдаёт строки одним списком в порядке отображения, а
иерархию несут `node.level`, `posInSet` и `setSize`.

Из этого следует обязанность потребителя: в плоском DOM группы нет, и структуру
дерева диктору сообщают ровно эти три атрибута — `aria-level`, `aria-posinset`,
`aria-setsize`. Пропустив их, вы получите список, который выглядит деревом и не
является им.

## Отметки — часть модели, а не чекбокса

`checkStates`, `getCheckState`, `setChecked`, `toggleChecked`, `getCheckedKeys`,
`getHalfCheckedKeys` живут здесь. Значит своя разметка получает наследование и
частичное состояние даром: рисуете свой квадратик, состояние берёте из модели.
`checkStrictly` связь отключает — каждый узел отвечает сам за себя.

Состояние объявляется **на самом узле** (`aria-checked` на `treeitem`), а видимый
квадратик остаётся декоративным: вкладывать интерактивный чекбокс внутрь
роли-виджета нельзя — роль объявляет потомков презентационными.

## Ленивая подгрузка

`lazy` плюс `load` — и модель считает узел разворачиваемым, пока не доказано
обратное; лист объявляется полем данных. `ensureLoaded` грузит ветку по первому
раскрытию и повторного запроса не делает, `isLoadingKey` говорит, что запрос идёт.
Загруженные дети живут в состоянии модели, а не дописываются в `data`: проп
реактивным быть не обязан.

## Направляющие модель не рисует

Опция `branchColorFor` — единственное, что модель знает о виде: она копит цепочку
цветов предков и кладёт её в `row.branchColors`. Не задана — цепочка пуста.
Как из неё сделать линии, колена или ничего, решает потребитель.

## Перемещение узлов правит ваши данные

`moveNode`, `appendNode`, `removeNode` и вставки перекладывают элементы **в
переданном массиве**, а не в своей копии: модель данные не дублирует. Отсюда
условие — данные должны быть реактивными (`ref`, `reactive` или пропы
компонента). На обычном массиве перестановка произойдёт, но пересчитывать модель
будет нечему, и список строк останется прежним.

## Чего композабл не делает

- **не рендерит ничего** — ни строк, ни ролей, ни `aria-*`;
- **не трогает DOM и не слушает события.** Фокус, клавиатура, перетаскивание и
  виртуализация — это [`useRovingFocus`](./keyboard.md),
  [`useDragSort`](./drag-sort.md) и [`useVirtualList`](./virtual-list.md), и
  `GrTree` собирает дерево именно из них плюс эта модель;
- **не нормализует данные.** Форму объектов описывает адаптер, копий модель не
  делает.

## Серверный рендер

Обращений к среде нет вовсе: ни `document`, ни `window`, ни наблюдателей. Модель
считается одинаково на сервере и на клиенте, поэтому первый клиентский кадр
совпадает с серверным сам собой.
