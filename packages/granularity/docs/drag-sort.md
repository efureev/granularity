# `useDragSort` — перестановка указателем и с клавиатуры

Модель переноса поверх [`useDragGesture`](./drag-gesture.md). Композабл владеет **механикой**:
порогом начала, попаданием указателя в элемент, автопрокруткой у краёв контейнера и состоянием
переноса. **Смысл** остаётся у компонента — что считать целью, какими клавишами это делается и что
сказать в живой регион.

В пакете на нём работают `GrSortableList` (цель — индекс вставки) и `GrTree` (цель — узел плюс
зона `prev`/`inner`/`next`).

`GrTransfer` его **не** берёт, и это стоит знать, планируя следующий перенос: `resolveTarget`
получает попадание, но не точку указателя, а панель-приёмник там выбирается прямоугольником под
точкой — `hitTest` при промахе отдаёт ближайшую строку, и указатель над пустой правой панелью
резолвился бы в строку левой. Понятия «куда ещё можно ронять» у примитива нет. Поэтому перенос
между контейнерами собирается из `useDragGesture` и чистых функций геометрии.

```ts
import { useDragSort } from '@feugene/granularity'

const sort = useDragSort<string, number>({
  items: () => keys.value,
  elementFor: key => rowEls.get(key),
  scroller: () => scrollerEl.value,
  resolveTarget: (hit, source) => insertionIndex(hit, indexOf(source), keys.value.length),
  onDrop: (source, to) => reorder(indexOf(source), to),
})
```

```vue
<div v-for="key in keys" :key="key">
  <button @pointerdown="sort.startFrom(key)">⠿</button>
</div>
```

## Почему граница проведена именно так

У списка цель переноса — число (индекс вставки), у дерева — пара «узел и зона». Клавиатура тоже
разная: в дереве `Space` уже занят чекбоксом, поэтому там раскладка аутлайнера (`Shift` со
стрелкой двигает узел сразу), а в списке `Space` берёт и кладёт. Общая у них механика, а не
семантика — обобщать семантику значило бы завести опцию на каждое расхождение.

Отсюда два следствия, которые видно в API:

- **`resolveTarget` — обязательный колбэк.** Композабл отдаёт попадание (`key` и доля вдоль
  элемента), а нарезать его на зоны — дело компонента: список делит пополам, дерево на трети.
- **Данные композабл не меняет.** Он сообщает «источник и цель», перестановку делает потребитель.
  Обычная перестановка массива — `moveItem` из того же модуля геометрии.

## Порог: нажатие — ещё не перенос

Между `pointerdown` и первым движением строка остаётся кликабельной. Перенос начинается, только
когда указатель ушёл дальше порога (по умолчанию 4px) — иначе клик по ручке превращался бы в
микроперестановку от дрожания руки.

## Два исхода и `Esc`

Отпускание переносит, обрыв (`pointercancel`) — нет. Сверх этого композабл слушает `Esc` в
capture-фазе, пока идёт перенос указателем: браузер на `Esc` не шлёт `pointercancel`, а бросить
начатое пользователь вправе.

## Автопрокрутка

Если задан `scroller`, у его краёв список едет сам, и скорость растёт по мере приближения к краю.
Прокрутка живёт в своём кадре (`requestAnimationFrame`), а не в обработчике движения: у края
указатель обычно стоит неподвижно, событий больше нет — а ехать надо.

## Клавиатурный режим

`grab(key)` → `setTarget(t)` → `drop()` или `cancel()`. Раскладку клавиш composable не знает: он
даёт состояние, а какие клавиши его меняют, решает компонент. Указатель не перебивает начатый
клавиатурный перенос — и наоборот.

## API

| Опция | Назначение |
| --- | --- |
| `items` | ключи в порядке отображения |
| `elementFor` | DOM-узел по ключу; неотрисованные пропускаются |
| `orientation` | `vertical` (по умолчанию) или `horizontal` |
| `scroller` | контейнер для автопрокрутки; нет — нет и автопрокрутки |
| `disabled`, `canDrag` | запрет на весь список и на отдельный элемент |
| `threshold` | порог начала переноса, px |
| `resolveTarget` | попадание → цель; `null` — сюда нельзя |
| `onDrop` | перенос состоялся |
| `onUpdate` | состояние изменилось: подсветка и объявления |

| Возвращает | Назначение |
| --- | --- |
| `source`, `target`, `mode` | что переносим, куда и чем (`pointer` / `keyboard`) |
| `isActive` | идёт ли перенос |
| `startFrom(key)` | обработчик на `@pointerdown` ручки или строки |
| `grab`, `setTarget`, `drop`, `cancel` | клавиатурный перенос |

Цели сравниваются **по ссылке**. Если цель — объект, возвращайте из `resolveTarget` ту же ссылку,
пока смысл не изменился (третий аргумент — прежняя цель): иначе подсветка и объявления будут
дёргаться на каждом движении указателя.

## Чего композабл не делает

- не рисует ни ручку, ни индикатор вставки;
- не объявляет ничего в живой регион — текст знает только компонент;
- не отслеживает несколько указателей: pinch и swipe это другая задача;
- не работает поверх виртуализации: цель может быть не отрисована. `GrSortableList` поэтому и не
  виртуализируется, а `GrTree` роняет узел только на видимую строку.

## Доступность

Перенос обязан иметь клавиатурный эквивалент — иначе им не может пользоваться никто, кроме
владельца мыши. Как это сделано в пакете: `GrSortableList` — `Space` взять, стрелки двигать,
`Space` положить, `Esc` отменить; `GrTree` — `Shift` со стрелкой. Оба объявляют результат в живой
регион через [`useAnnouncer`](./announcer.md). Полная таблица — в [`keyboard.md`](./keyboard.md).
