# `useDragGesture` — указательный жест: нажал, повёл, отпустил

Скелет непрерывного жеста мышью, пальцем или пером. Композабл владеет только водопроводом
событий: подписка, фильтр кнопки, отписка и то, чем отпускание отличается от обрыва. Что считать
значением и что делать с движением — целиком дело потребителя: примитив не рендерит ничего и не
знает ни координат, ни единиц.

В пакете на нём работают `GrSlider` (перетаскивание бегунка), `GrSplitter` (перетаскивание
разделителя), `GrImageViewer` (панорамирование кадра мышью и пером; многопальцевые pinch и свайп
там ведёт свой трекер — у него другая модель) `GrToaster` (смахивание уведомления к краю экрана), `GrCarousel` (листание кадра протяжкой) и
`GrTransfer` (перенос строк между двумя панелями).

```ts
import { useDragGesture } from '@feugene/granularity'

const drag = useDragGesture({
  disabled: () => props.disabled,
  onStart: event => selectTarget(event),
  onMove: (event) => {
    event.preventDefault()
    setValue(valueFromPointer(event))
  },
  onEnd: () => emit('change', value.value),
  onCancel: () => restore(valueBeforeDrag),
})
```

```vue
<div class="[touch-action:none]" @pointerdown="drag.start">
…
</div>
```

## Два исхода, а не один

Главное, ради чего примитив существует: у жеста **две разные концовки**, и путать их нельзя.

| Событие | Что произошло | Обработчик |
| --- | --- | --- |
| `pointerup` | пользователь отпустил — жест завершён | `onEnd`: значение коммитится |
| `pointercancel` | указатель забрал браузер: системный жест, скролл, потеря окна | `onCancel`: возврат к состоянию до нажатия |

Обрыв — не редкость на десктопе и норма на тач-устройствах: вертикальный свайп по элементу уходит
в прокрутку страницы, и браузер отзывает указатель. Если ловить только `pointerup`, оборванный
жест оставит наполовину применённое значение, а компонент — подписанным на движения.

**Что значит «вернуться», решает потребитель.** У слайдера и сплиттера обрыв откатывает значение к
тому, что было до нажатия. У панорамирования картинки — нет: кадр уже сдвинут пользователем, и
возврат к исходной точке читался бы как рывок, а не как отмена. Примитив даёт две разные концовки;
какой смысл в них вкладывать — знает только компонент.

Поэтому цели жеста нужен `touch-action: none` (в разметке — `[touch-action:none]`): без него
браузер отдаёт вертикальное движение прокрутке, и пальцем компонент неуправляем.

## Слушатели на `window`, а не на элементе

Указатель уходит за границы дорожки постоянно — быстрым движением, у края экрана, при
перетаскивании за пределы окна. Подписка на сам элемент теряла бы жест на первом же таком
движении.

Захват указателя (`setPointerCapture`) решает ту же задачу, но привязывает жест к живому DOM-узлу,
а он в середине жеста может перерисоваться. Слушатели на `window` этого не боятся.

Снимаются они дважды: при завершении любым из исходов и при остановке области видимости
(`onScopeDispose`). Второе — не подстраховка: компонент, размонтированный посреди жеста, иначе
оставил бы три висящих слушателя. Обработчики при этом **не** зовутся: коммитить и откатывать
уже некуда.

## API

| Опция | Назначение |
| --- | --- |
| `disabled?` | геттер: жест не начинается вовсе (`disabled` / `readonly`) |
| `onStart?` | нажатие прошло проверки; вернуть `false` — жест не начинать |
| `onMove` | движение указателя, пока жест идёт |
| `onEnd?` | отпускание: значение коммитится |
| `onCancel?` | обрыв: что он означает, решает потребитель (см. выше) |

| Возвращает | Назначение |
| --- | --- |
| `isDragging` | идёт ли жест; удобно для класса состояния и `data`-атрибута |
| `start` | вешается на `@pointerdown` цели |
| `stop(commit?)` | принудительное завершение; по умолчанию — как обрыв, без коммита |

Жест начинается **только основной кнопкой**: правый и средний клик перетаскиванием не считаются.
Повторный `stop()` и второе нажатие во время жеста ничего не делают.

`onStart` с возвратом `false` нужен там, где нажатие ещё не означает жест: попадание мимо цели,
выбор конкретного бегунка, запрет по данным. Отличать этот случай от `disabled` важно — второе
выключает элемент целиком.

## Чего примитив не делает

- **не вызывает `preventDefault`** — и он нужен всем по-разному: слайдер и сплиттер гасят выделение
  текста на движении, просмотрщик — родное перетаскивание картинки на нажатии. Одна строка у
  потребителя дешевле опции, меняющей поведение невидимо;
- **не считает координаты и дельты** — это арифметика компонента (`valueFromPointer`,
  `sizeFromPointer`);
- **не знает про порог начала жеста** — он нужен сортировке, где нажатие может оказаться обычным
  кликом, и появится вместе с ней;
- **не отслеживает несколько указателей** — pinch и swipe это другая задача с собственной моделью.

## SSR

Безопасен: `window` трогается только внутри обработчика `pointerdown`, то есть уже в браузере.
В `setup` композабл не обращается ни к чему средозависимому, отдельного guard'а не требует.
