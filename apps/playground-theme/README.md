# playground-theme

Рабочий пример из [`modes.md`](../../packages/granularity/docs/modes.md) ядра и [`themes.md`](../../packages/granularity-tokens/docs/themes.md) пакета токенов:
свои режимы поверх темы пакета, тема каталога и своя тема приложения — в одной сборке granum.

```bash
yarn build:tokens && yarn build:granularity && yarn build:chrono && yarn build:charts   # стенды работают с собранным dist
yarn workspace @feugene/granularity-playground-theme dev
yarn workspace @feugene/granularity-playground-theme test:run
```

## Что показано

| Файл | Что в нём смотреть |
| --- | --- |
| `theme.config.ts` | режимы данными: `ocean` поверх тёмного (`extendMode`), высококонтрастный `contrast` с нуля (`createMode`) |
| `granum.config.ts` | провайдеры — ядро и спутники `chrono` и `charts`: свой режим доходит до спутников без строки о них в рецепте; темы сборки — `themes`: основная `slate` с режимами `ocean` и `contrast` в `modes.define` (`ocean.definition` и `ocean.fallbacks`), дополнительные — тема каталога `clay` и своя тема (`loadTheme`), каждая своим листом |
| `src/themes/brand/` | своя тема приложения: `theme.json` с `"extends": "slate"`, `root.json` и `modes/*.json` — только отличия |
| `src/main.ts` | `granularityThemePlugin` с манифестом сборки `virtual:granum/themes`: у островов дополнительных тем — пропсы по умолчанию их темы |
| `src/granularity.ts` | общий лист `virtual:granum.css` и листы дополнительных тем `virtual:granum/themes.css` |
| `vite.config.ts` | ранний скрипт режима в `<head>` — опция `themeScript` плагина granum |
| `src/App.vue` | переключатель режимов из манифеста, календарь, поле даты и график в текущем режиме, острова дополнительных тем `<GrConfigProvider theme="…" mode="…">`: у «Глины» загрузка — свет по подписи, группа — лоток |
| `src/__tests__/theme.test.ts` | автопроверка: полнота ролей, контраст по WCAG, что granum положил режимы и темы под их пары и в свои листы |
| `src/__tests__/themeRecipes.test.ts` | рецепты раздела «Свои режимы в конфиге» `modes.md` и «Своя тема приложения» `themes.md` на настоящем granum |

## Режим или тема

Режим — вариант темы: он встаёт под свою пару `slate-ocean` и берёт
токены компонентов у режима `extends`. Так делаются тёмная, высококонтрастная или
сезонная версия той же дизайн-системы.

Тема — другой дизайн-язык: свои примитивы (здесь — скругления), свои режимы,
свои пропсы компонентов по умолчанию. Основная тема у сборки одна — `slate`, под
`:root` и в общем листе; `clay` и `brand` — дополнительные: каждая своим листом,
полными блоками своих пар. Их включает остров `GrConfigProvider theme="…"` или
`useTheme().setTheme('clay')` на корне — тогда лист грузится по адресу из манифеста.
Сделать тему основной — пометить её `default: true` в `themes`.

Эта страница показывает дополнительные темы всегда, поэтому импортирует их листы
модулем `virtual:granum/themes.css`. Приложению, которое включает тему по выбору,
импорт не нужен: остальные страницы за неё не платят.

Правка файлов `src/themes/brand/` в dev перезапускает конфиг: `loadTheme`
перечисляет их в `sources`, и плагин granum за ними следит.

## Проверка — не глазами

`src/__tests__/theme.test.ts` — чек-лист из документации, доведённый до
исполняемого вида:

- **полнота**: список ролей берётся из `@feugene/granularity-tokens`, поэтому
  проверка не устареет, когда в пакете появится новая роль;
- **отличия**: в `modes.define` уходят только роли, отличные от базы;
- **контраст**: основной и вторичный текст на всех поверхностях, `-fg` на своей
  заливке **включая hover/active** (формула `color-mix` повторена в тесте),
  `-text` на `-light` и на фоне, заливка как индикатор (3:1), видимость
  focus-ring, различимость `primary` и `info`;
- **сборка**: блоки пар режимов основной темы в общем листе, блоки дополнительных
  тем — только в своих листах; токены кнопки «Сланца» у `brand` — по цепочке
  `extends`, у «Глины» — свои; пропсы по умолчанию «Глины» — в манифесте тем.
