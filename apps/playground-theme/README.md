# playground-theme

Рабочий пример из [`packages/granularity/docs/theming.md`](../../packages/granularity/docs/theming.md):
как добавить приложению **третью** тему поверх встроенных `light`/`dark`.

```bash
yarn build:granularity          # витрина и playground'и работают с собранным dist
yarn workspace @feugene/granularity-playground-theme dev
yarn workspace @feugene/granularity-playground-theme test:run
```

## Что показано

| Файл | Что в нём смотреть |
| --- | --- |
| `src/styles/theme-ocean.css` | тема как **набор семантических ролей**: ни примитивов, ни `hover`/`active` — их пакет выведет сам |
| `src/main.ts` | подключение темы обычным импортом CSS после foundation-слоя пакета |
| `uno.config.ts` | почему для третьей темы **не** годится `themes.themeFiles` |
| `src/theme.ts` | свой контроллер тем: `useTheme()` из пакета типизирован как `'light' \| 'dark'` и третью тему не переключит |
| `index.html` | инлайновый скрипт, который ставит тему до первого рендера — иначе вспышка чужой темы |
| `src/__tests__/theme.test.ts` | автопроверка темы: полнота набора ролей + контраст по WCAG |
| `src/App.vue` | «плотный экран» — заливки, мягкие подложки, контролы и вторичный текст рядом |

## Почему тема подключается импортом, а не пресетом

`themes.themeFiles` у `presetGranularNode` — карта «имя темы → файл», которая
**заменяет** CSS уже существующей темы. Список тем получается пересечением
`themes.names` с тем, что объявил granular-провайдер, поэтому нового имени там
взяться неоткуда.

Проверено сборкой: с `themeFiles: { dark: './theme-ocean.css' }` в бандл
попадает селектор из вашего файла, но встроенная тёмная тема пакета
**пропадает целиком**. Это инструмент «перекрасить тему», а не «добавить».

Для третьей темы остаётся обычный CSS-слой приложения — что и делает `main.ts`.
Конфликта селекторов нет: `[data-theme='ocean']` и `[data-theme='dark']` никогда
не совпадают.

## Проверка темы — не глазами

`src/__tests__/theme.test.ts` — тот самый чек-лист из документации, доведённый
до исполняемого вида:

- **полнота**: список ролей берётся из `@feugene/granularity/tokens`, поэтому
  проверка не устареет, когда в пакете появится новая роль;
- **лишнее**: тема не должна объявлять примитивы и производные состояния;
- **контраст**: основной и вторичный текст на всех поверхностях, `-fg` на своей
  заливке **включая hover/active** (формула `color-mix` повторена в тесте),
  `-text` на `-light` и на фоне, заливка как индикатор (3:1), видимость
  focus-ring, различимость `primary` и `info`.

Проверено, что тест ловит ошибки: подмена `--gr-muted-fg` на значение из
светлой темы и `--gr-success-fg` на белый роняют его сразу.
