# `@feugene/granularity-showcase-icons`

Правила иконок `i-lucide-*` как провайдер granum. Пакет приватный: он нужен
только витрине и в реестр не уезжает.

## Зачем он есть

granum своей реализации движка не содержит, а `@feugene/granum-engine-wind`
вендорит `preset-wind3` — правил иконок там нет. Витрина пользуется классами
`i-lucide-*` в семи десятках мест: демо показывают потребителю, как ставить
иконку классом.

Правила можно передать фабрике движка — `windEngine({ rules })`, — и до этого
пакета витрина так и делала. Но у этого есть цена, которую видно в строке
времени сборки: свои правила меняют **отпечаток словаря** приложения, он
перестаёт совпадать с записанным в манифестах пакетов, и granum честно
пересчитывает классы всех восьми пакетов по их файлам.

На витрине это было 547 мс каждой сборки при нулевой разнице в результате
(`lost` и `gained` в отчёте пусты). Правила, приехавшие **от провайдера**,
отпечаток приложения не трогают: они добавляются ко входу генератора, а словарь
движка остаётся ванильным, и манифестам снова верят (A-E3, E-9).

| | `windEngine({ rules })` | провайдер |
|---|---|---|
| `prepare` | 694 мс (из них `manifests` 586) | 101 мс (`manifests` 2) |
| всё время granum | 1069 мс | 550 мс |
| классов в CSS | 1697 | 1697 |

## Как устроен

Компонентов у провайдера нет вовсе — только модуль правил, на который ссылается
манифест (`engine.module`). Приложение грузит его по этой ссылке, если
**диалекты совпадают**: провайдер объявляет `unocss/preset-wind3+granum@66`,
тот же, что у пакетов дизайн-системы.

Две вещи, на которых легко споткнуться:

* **Имя экспорта.** granum берёт у модуля `rules`, `variants` и `preflights`
  (M-E4). Экспорт под другим именем грузится успешно и молча ничего не даёт:
  отчёт пишет `rulesLoaded: true`, а иконки исчезают из CSS.
* **Граница browser/node.** `node:fs` в коде провайдера запрещён (B-16), и
  сборка на этом падает. Набор иконок поэтому импортируется из ESM-входа
  `@iconify-json/lucide`, а не читается с диска и не берётся прямым импортом
  JSON: атрибут `with { type: 'json' }` бандлер срезает, и Node отказывается
  грузить получившийся модуль.
