# design

Приложение дизайн-системы `@feugene/granularity`: основы и компоненты с макетами
всех версий дизайна — реализованной и экспериментальных.

```bash
yarn dev:design            # собирает пакет и поднимает приложение
yarn workspace @feugene/granularity-design test:run
```

Как витрина, приложение работает с собранным `dist` пакета: `dev` пересобирает его
сам, а после правки библиотеки при запущенном сервере — `yarn build:granularity`.

## Темы в браузере

```bash
yarn workspace @feugene/granularity-design test:e2e          # axe и эталоны страниц тем
yarn workspace @feugene/granularity-design test:e2e:update   # переснять эталоны
```

`e2e/themes.spec.ts` открывает `/themes/<slug>` каждой темы каталога: axe с
`color-contrast` по островам режимов и эталон раздела «Компоненты» в каждом режиме.
Новая тема каталога попадает в прогон сама; эталоны для неё снимаются тем же
коммитом. Слой локальный, как визуальный гейт витрины: эталоны
`*-chromium-darwin.png` снимаются на машине владельца, и перед съёмкой `dist`
пакета обязан быть свежим (`yarn build:granularity`).

## Что где

| Раздел | Откуда данные |
| --- | --- |
| Основы — цвет, типографика, пространство, движение, иконки | `@feugene/granularity-tokens`: образцы и таблицы строятся из реестра и данных темы `slate`, контраст считается по их значениям; острова режимов — по манифесту сборки `virtual:granum/themes` |
| Темы — каталог и `/themes/<slug>` | `grThemeCatalog`; режимы и основы темы, настоящие компоненты под её парой. Весь каталог — темы сборки (`themes` в `granum.config.ts`): `slate` основная, остальные дополнительные, их листы приложение импортирует сразу (`virtual:granum/themes.css`) и показывает островами `<GrConfigProvider theme="…">` |
| Компонент → «Спецификация» реализованной версии | настоящие компоненты пакета; «Когда брать» и «Когда взять другое» — из `docs/components/GrX.md` |
| Компонент → «Спецификация» концепта и сравнение версий | разделы `docs/design/GrX.md` пакета, собираются в бандл — копий текста нет |
| Компонент → вкладки макетов | `src/designs/<компонент>/<версия>/*.vue` |

## Макеты

Каждая версия — папка в `src/designs/<компонент>/`: `concept.css` — общие стили
версии, `<Макет>.vue` и одноимённый `.css` — сам макет. Список версий и макетов
с подписями — `src/app/catalog.ts`; тест `src/__tests__/catalog.test.ts` держит
его в согласии с файлами и с разделами `docs/design`.

Макет рисуется в shadow DOM (`src/app/parts/BoardFrame.vue`). У версий одинаковые
имена классов и анимаций — `.gb`, `.doc`, `gr-spin`, — и в общем документе они
перебили бы друг друга и утилиты приложения. Внутрь shadow root не проходит и
сброс стилей: макеты нарисованы поверх стилей браузера по умолчанию. Содержимое
попадает туда телепортом и остаётся частью приложения, поэтому интерактивные
макеты — состояния, песочницы — живые.

Шрифты (Inter, JetBrains Mono) подключает `index.html`: `@font-face` из shadow DOM
Chrome не применяет.

Утилиты granum сканируются только в `src/app`: классы макетов движок принял бы за
свои.

## Новый компонент

1. Документ `packages/granularity/docs/design/GrX.md`: раздел на версию и таблица
   сравнения в разделе «… версии рядом».
2. Папки версий в `src/designs/<id>/` и запись в `catalog`.
3. Документ — в `designDocs` и `componentDocs` в `src/app/docs.ts`; живая
   спецификация реализованной версии — в `src/app/specs.ts`.
