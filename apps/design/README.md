# design

Приложение дизайн-системы `@feugene/granularity`: основы, темы каталога и
компоненты — на настоящих компонентах пакета, в каждой теме и каждом режиме.

```bash
yarn dev:design            # собирает пакет и поднимает приложение
yarn workspace @feugene/granularity-design test:run
```

Как витрина, приложение работает с собранным `dist` пакета: `dev` пересобирает его
сам, а после правки библиотеки при запущенном сервере — `yarn build:granularity`.

## Тема в адресе

Тема — первый сегмент пути: `/clay/foundations/typography` — типографика «Глины»,
ссылку можно отдать. Адрес — единственный источник темы: роутер до отрисовки
страницы грузит данные темы (`loadThemeData`) и включает её у документа
(`useTheme().setTheme`), переключатель в шапке и кнопка «Применить ко всему
приложению» на странице темы ведут на ту же страницу под другой темой. Режим в
адрес не входит — это запомненный выбор кнопки в шапке. `/` и адреса без темы
(`/foundations/color`, `/themes/clay`) ведут в последнюю выбранную тему; выбор в
другой вкладке переводит на неё и адрес этой.

Сохранённый выбор ставит на корень скрипт темы granum до первого кадра (`themeScript`
в `vite.config.ts`): перезагрузка в тёмном режиме не мигает светлым. Скрипт вставляет и
ссылку на лист дополнительной темы, а лист начинается объявлением слоёв granum. В dev
сброс приходит из JS уже после этой ссылки, поэтому порядок `@layer reset, granum`
объявлен в `index.html`. Без этой строки кнопки после перезагрузки в «Глине» теряют
отступы и вес: сброс перебивает утилиты.

## Темы в браузере

```bash
yarn workspace @feugene/granularity-design test:e2e          # axe и эталоны страниц тем
yarn workspace @feugene/granularity-design test:e2e:update   # переснять эталоны
```

`e2e/themes.spec.ts` открывает страницу каждой темы каталога: axe с
`color-contrast` по островам режимов и эталон раздела «Компоненты» в каждом режиме.
`e2e/switch.spec.ts` — смена темы: адрес, пара на корне, значения основ, вид кнопки,
перезагрузка с заблокированным JS приложения (пару и лист ставит скрипт темы), корень,
режим, другая вкладка. Он идёт дважды — на dev-сервере и на сборке (проект `build`,
`vite preview`): скрипт темы на сборке стоит после стилей, а в dev стили приходят
позже него, и порядок слоёв держится по-разному.
Новая тема каталога попадает в прогон сама; эталоны для неё снимаются тем же
коммитом. Слой локальный, как визуальный гейт витрины: эталоны
`*-chromium-darwin.png` снимаются на машине владельца, и перед съёмкой `dist`
пакета обязан быть свежим (`yarn build:granularity`).

## Что где

| Раздел | Откуда данные |
| --- | --- |
| Основы — цвет, типографика, пространство, движение, иконки | `@feugene/granularity-tokens`: образцы и таблицы строятся из реестра и данных темы адреса (`loadThemeData`, `src/app/viewedTheme.ts`), контраст и колонки режимов — по её режимам; острова режимов — по манифесту сборки `virtual:granum/themes` |
| Темы → каталог `/<тема>/themes` | `orderedThemes` (основная первой): карточка — образец интерфейса островом темы в выбранном режиме и паспорт; «Темы рядом» — данные всех тем (`useThemeViews`): шрифт, угол контролов, главный цвет по режимам, значения и пропсы компонентов |
| Темы → страница `/<тема>/themes/<slug>` | «Обзор» — режимы, основы и компоненты под парой темы, разделы её значений компонентов со ссылкой на страницу компонента; «Токены» — роли по режимам, примитивы и производные из данных темы (`themeTokens.ts`); «Хуки» — ручки приложения всех компонентов ядра, тема их не задаёт |
| Компонент → карточки тем | `builtThemes` (`src/app/themes.ts`): основная первой; характер — строка «Характер» таблицы `docs/design/GrX.md`; образец — `preview` из `src/app/specs.ts` островом `<GrConfigProvider theme="…">` |
| Компонент → «Обзор» | песочница и спецификация на настоящих компонентах в теме адреса; «Когда брать» и «Когда взять другое» — из `docs/components/GrX.md`; ступени снимаются с кнопки на странице |
| Компонент → «Стиль темы» | пропсы от темы (`componentDefaults` в данных темы), острова её режимов, раздел темы из `docs/design/GrX.md` |
| Компонент → «Темы рядом» | один шаблон в каждой теме сборки и таблица «… темы рядом» из `docs/design/GrX.md` |
| Компонент → «Токены» | `grComponentTokens` пакета и значения темы адреса (`loadThemeData`): `root` или режимы; образец цвета, тени и угла считается браузером под парой своего режима |
| Компонент → «Хуки» | хуки компонентов страницы из `grComponentTokens`: значение без хука и почему оно не тема (`literal`) |

Вкладка компонента — в адресе: `/<тема>/components/button?tab=tokens`. Адрес с id темы после
компонента (`/slate/components/button/clay`) ведёт на страницу компонента в этой теме.

## Новый компонент

1. Документ `packages/granularity/docs/design/GrX.md`: раздел на тему каталога —
   заголовок кончается её id («Чертёж — тема `blueprint`») — и таблица «… темы рядом»
   со строкой «Характер».
2. Запись в `catalog` (`src/app/catalog.ts`): `exports` — компоненты, чьи токены
   показывает вкладка «Токены».
3. Документы — в `designDocs` и `componentDocs` в `src/app/docs.ts`; вкладки — в
   `componentViews` (`src/app/specs.ts`).

`src/__tests__/catalog.test.ts` держит согласие каталога с документами и реестром
токенов, `e2e/component.spec.ts` — axe по каждой вкладке компонента, `e2e/catalog.spec.ts` —
по каталогу тем и вкладкам страницы темы.
